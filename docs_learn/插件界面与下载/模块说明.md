# 插件界面与下载

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

学习 Workbench／外部 Webview 的实例身份、导航授权、状态机及下载处理。

## 设计逻辑与执行流程

`ora-surface` 是不依赖 Tauri 的纯 Rust 状态层：管理 definition、实例 registry、navigation policy、操作状态机和下载模型。Desktop host 执行创建／关闭 Webview、文件传输等 effect。

Workbench 读取已验证的包内资源并声明 bridge 能力；RemoteSite 只允许合同中的 HTTPS origins。Webview label 只是名字，授权必须回查 registry 和来源，不能把 label 前缀当作权限证明。

一个 workbench 实例只绑定一个 plugin process generation，不能静默换代。OperationId／ViewGeneration 阻止旧请求完成结果覆盖重建页面。registry 锁只保护 map 与纯状态变化，不在锁内执行 I/O。

下载开始即冻结页面 URL、处理规则和身份，避免页面后来导航改变已开始下载的去向。`Staging → AwaitingChoice 或 Processing → Settled`，用户选择的转换保证只执行一个动作。

## 数据库表与持久化

| 数据 | 保存位置 | 生命周期 |
| --- | --- | --- |
| SurfaceDefinition、入口、导航／下载合同 | 插件包声明与 assets | 安装验证时读取 |
| SurfaceRegistry、实例 ID、operation ID、generation、下载状态机 | 内存 | 当前 Desktop 进程／页面实例 |
| Webview 私有数据、下载 staging 与最终文件 | Desktop host 管理的文件位置 | 依宿主文件／下载策略保存与清理 |
| 插件业务配置 | 插件 `store.json` | 配置模块负责，不是 Surface 状态表 |

当前 SQLite 没有 surfaces、webviews 或 downloads 表。`effect_targets` 所指 Target 是交付消费者，不等于 UI 的 SurfaceInstance，不可因为名称类似就建立错误关联。

## 目前存在的缺陷与限制

- **已确认的限制**：实例状态与计数器是进程内数据，数据库无法还原上一进程所有未完成下载／页面操作。
- **已确认的兼容边界**：generation 变更或旧 OperationId 完成会被拒绝，插件重启不能靠复用旧实例权限绕过。
- **设计风险**：安全依赖 registry 身份、导航与 bridge 能力同时正确；仅验证 URL 或 label 不足以保证操作来自被授权实例。
