## 模块职责

解释何时真正创建会话、只读加载、取消、停止、重命名、删除与历史降级。

## 设计逻辑与执行流程

未发送的聊天草稿不是 provider Session。首次发送（或工作流节点执行）才 `session/new`；握手和可选模型配置成功后保存 Ora Session，并把同一条 route 交给 Actor。创建中断时 release guard 释放尚未对外暴露的 provider Session。

- **load**：读取 Ora 自有历史，不向 Agent 请求恢复。无 Actor 时有限回放；有 Actor 时先回放 durable cutoff，再跟随进行中的事件。
- **prompt**：需要时才 attach／restore provider；如果 provider 无法恢复，创建替代会话并用历史交接。
- **cancel**：取消当前轮，记录 cancelled 边界，健康 Actor 可继续用。关闭跟随视图只取消该视图订阅。
- **stop**：停止／卸载 Session route，能力允许时关闭 provider Session；不删除 Ora 对话记录。
- **rename**：先 title-only 数据库写入，再广播失效通知让客户端重取；用户重命名锁定自动取标题窗口。
- **delete**：串行 unload 后软删除 Ora 行并移除 Ora history，provider 自有历史保留。

自动标题只在新会话的短暂窗口工作；符合条件的首轮后可在 3 秒和 10 秒发起有界 fallback。重启、切换、停止后不会重新开启。

## 数据库表与持久化

| 表／文件 | 字段 | 业务含义与写入时机 |
| --- | --- | --- |
| `sessions` | `id,workspace_id` | 创建时固定会话身份与归属 |
| `sessions` | `agent_cli,agent_session_id` | 创建、换绑、provider 重建提交时更新 |
| `sessions` | `status` | `0=Running`，`1=Stopped`；启动校正残留值 |
| `sessions` | `title,created_at,updated_at,is_deleted` | 标题、审计、软删除 |
| `sessions` | `history_degraded_reason` | NULL 可写；非 NULL 保存降级原因并阻止后续 prompt |
| JSONL | Meta／Update／TurnEnded 等 | 保存实际对话及结束边界 |
| `workflow_node_runs` | `session_id` | 工作流节点确认接纳 prompt 后才发布其会话绑定 |

没有 warm-session 专用表。未发布工作流 Session 集合、活动轮次、跟随者、自动标题窗口都在内存。

## 目前存在的缺陷与限制

- **已确认的限制**：`status` 只表示运行绑定，无法独自表达“正在回复”“历史损坏”“标题还在等待”；这些状态不能合并猜测。
- **已确认的限制**：重启不会续跑上次未完成的 prompt；读取旧对话也不意味着 provider 已经准备好。
- **已确认的残留风险**：Ora history 删除是 best effort，失败只告警，数据库软删除后可能残留无法从普通列表访问的文件。
- **已确认的标题限制**：重命名锁定窗口是内存协议，已恢复会话直接禁用自动标题获取。
