# Mission: 深入理解 Ora 插件系统

## Why
能够在技术面试中完整、准确地讲清 Ora 插件系统的架构、调用链和关键取舍，并能承受沿着 Agent 插件继续深挖的追问。其次，把这套理解转化为后续开发和扩展插件能力时的判断力。

## Success looks like
- 不看代码画出插件从市场清单、安装发现、贡献验证到运行或静态消费的完整架构图。
- 清楚区分插件包、插件贡献、插件进程、Agent CLI 进程与 ACP Connection，并解释各自所有权。
- 比较 Agent、Skill、MCP、Webview、Workbench、Hook 六类插件复用底座的方式和当前实现状态。
- 从一个面试问题出发，落到具体代码边界、设计动机、故障语义与安全取舍。
- 面对新增插件类型或扩展 Agent 契约的需求，能判断修改应落在哪一层并说明原因。

## Constraints
- 面试表达优先于逐行掌握代码；开发扩展能力作为第二优先级。
- 从零基础开始，不预设用户理解“插件、进程、协议、运行时、Manifest”等软件工程概念。
- 使用简体中文，一次只学习一个紧密概念，先白话和类比，再进入工程术语与源码。
- 每课包含真实代码证据、面试表达模板和主动回忆练习。
- 课程以 `project_learn` 分支的当前代码为准，明确标注文档与实现的漂移。

## Out of scope
- 暂不逐行讲解插件设置页的前端视觉实现。
- 暂不深入与插件主线无关的 Workflow、数据库 CRUD 和通用 Tauri 命令。
- 暂不把尚未实现的 MCP 运行时物化描述成已经落地的能力。
