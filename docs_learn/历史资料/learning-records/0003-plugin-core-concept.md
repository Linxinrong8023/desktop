# 已理解插件化的核心目的

## Learner response

用户能够独立解释：插件化设计通常不要求为了增加一个新 Agent 而修改 Ora 主程序；只需增加一个符合 Ora 规定形式的 Agent 插件。安装后，Ora 通过插件获得对应 Agent 的能力，并可借助插件与 Agent 通信。用户将 Agent 插件准确类比为连接 Ora 与 Agent 的“胶水层”。

## Demonstrated understanding

- 能区分 Ora 主程序与后来安装的插件。
- 理解插件系统通过预先约定的形式支持后续扩展。
- 理解 Agent 插件承担 Ora 与具体 Agent 之间的连接职责。
- 理解插件化的主要收益是减少新增 Agent 时对主程序核心代码的修改。

## Precision to add

“无需修改 Ora”成立的前提是新 Agent 的需求落在现有插件契约能够表达的范围内。如果新需求超出既有契约，仍可能需要扩展插件底座。另需注意，“胶水层连接外部 Agent”是 Agent 插件的特点，不能直接推广为所有插件类型的共同特征。
