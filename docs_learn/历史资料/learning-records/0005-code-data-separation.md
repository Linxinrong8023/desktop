# 已理解插件代码与数据分离，回滚能力需要校正

## Learner response

用户说明 `data` 是持久化数据，插件代码发生变化时数据可以保持不变，因此没有必要与插件代码放在一起。用户还推断，插件代码按版本分目录是为了出现问题时回滚到旧版本。

## Demonstrated understanding

- 理解插件代码和用户数据具有不同生命周期。
- 理解插件升级不应无意中覆盖或丢失跨版本数据。
- 理解分目录能让代码与数据的职责更直观。

## Precision corrections

- `installed` 中的插件包是只读代码；`data` 才是插件唯一的可写目录，而不是笼统的“可读数据”。
- 当前在线更新流程在新版本验证并提交后，会删除同一插件的所有其他版本目录。
- 因此，带版本的目录布局本身并不代表产品已经支持回滚。它当前用于明确包版本身份、校验 Manifest 与目录版本一致，并使新版本能够先安全落盘。
- 更新下载或验证失败时，旧安装保持不变；这是更新失败保护，不是更新成功后的版本回滚。

## Mastery status

已掌握。用户能够复述：成功更新后旧版本目录被删除、独立的 `data` 目录保持不变，这不构成版本回滚；更新流程的保证是新版本成功前保留旧版本，避免更新失败导致没有可用插件。
