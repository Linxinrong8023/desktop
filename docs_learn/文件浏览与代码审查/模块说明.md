# 文件浏览与代码审查

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

理解文件树、搜索、diff 和 Git 基线的权威来源，区分文件读取与对话存储。

## 设计逻辑与执行流程

桌面命令接收 task／project 身份及相对路径，由宿主解析权威工作目录，不能让前端传任意 root。路径验证与 canonical containment 在 `ora-utils`，有界读取、搜索和 watch 在 `ora-fs`。

任务视图读隔离 Workspace；无任务的草稿聊天读项目主 Workspace。watch 事件让查询缓存失效后重新读磁盘。它不是文件版本数据库。

普通文件引用向 prompt 发送 `path:range`，Agent 自行读取，UI 以引用 chip 显示；diff 引用会展开为小 patch，因为尚未保存的变化不能靠读取原文件复现。

代码审查通过 worktree 基线与真实 Git 状态比较，读写 Git 的接口由 workspace-diff handler 与 Git adapter 分离。Task title 不能代替 workspace 所有权，路径也不能按 title 拼接。

`ora-pty` 提供终端进程与会话基础能力。其类型／API 存在不代表终端输出已有永久存储，更不能把 PTY replay 和 Ora 聊天 JSONL 混为一体。

## 数据库表与持久化

| 介质／表 | 保存内容 | 更新时机 |
| --- | --- | --- |
| `tasks`、`workspaces`、`workspace_locations` | 根据身份解析实际 root | 项目／任务生命周期 |
| `worktrees` | `branch_name,base_commit_id` | 创建时保存不可变比较基线 |
| Git 对象／index／工作目录 | 代码版本、暂存与当前文件 | Git 和文件操作 |
| 文件查询缓存／watch／PTY 活动会话 | 内存 | 打开、变化通知、进程运行期间 |
| JSONL | 发到对话中的引用／diff 内容及 Agent 更新 | 真实 prompt 和对话记录 |

没有文件树表、全文搜索表、diff 表或 terminal_history 表。`workflow_node_runs` 的交互基线是另一个专用 JSON 文件机制，见工作流执行模块。

## 目前存在的缺陷与限制

- **已确认的限制**：文件面板提供有界文本视图／搜索，不能假定它加载任意大小二进制文件或整个仓库全文到数据库。
- **已确认的历史边界**：普通 `path:range` 引用不是那个时刻文件正文的快照；文件后来变化后，引用可能无法复现发送时内容。
- **设计风险**：文件可能在读／watch 间被外部修改或删除；路径验证保护访问边界，不保证内容从查询到使用保持不变。
- **已确认的持久化边界**：终端基础设施没有对应业务表，不能承诺进程重启后永久恢复完整终端输出。
