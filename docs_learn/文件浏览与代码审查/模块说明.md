## 用户看到的 diff，是否就是即将提交的内容？

用户在任务 W1 里审查改动，同时 Agent 继续修改文件。界面里点“提交”，如果直接提交全部工作目录，可能夹带刚产生、尚未看过的修改；如果后端接受任意 root 路径，还可能操作另一份仓库。

整体设计：后端按 Workspace 身份解析根，路径按相对合同校验；文件与 Git 是事实来源，watch 只通知失效。审查区分工作目录、index 和固定基线，提交只作用于当前暂存集合；隔离工作树变更前核对持久分支身份。

## 为什么前端不能直接传绝对 root？

### 当前实现与反例

前端已有路径，直接传给后端方便，但这把授权根选择权交给调用方。**当前实现**：业务身份定位 Workspace，用户文件参数为相对路径；共享路径组件校验穿越、canonical containment 等。目录浏览过滤 `.git` 和越界链接目标；复制跳过 symlink，删除不跟随链接，拒绝根目录与目录复制进自身。

| 输入 | 后端判断 |
| --- | --- |
| W1 + src/retry.ts | 从 W1 的位置合同解析 root，再限定在其中 |
| W1 + ../secret | 路径穿越拒绝 |
| W1 + 指向外部的静态 symlink | containment 检测不能通过 |
| 自报 root=/other/project | 不能替代 W1 的权威位置 |

**边界与缺口**：普通 canonical 检查和随后打开之间可能有并发替换窗口；不能宣称所有调用点抵御恶意同用户程序。**可能方案**是关键写入使用目录句柄相对打开、不跟随链接与文件身份复核；需保存/携带受信任根句柄和期望身份，成本是平台适配。能力不足时拒绝高风险操作，不降低成字符串前缀检查。

## watcher 为什么不能成为文件版本数据库？

### 当前实现与完整演算

watcher 发相对路径失效批次，rename 处理旧/新路径及父目录；前端按 Files owner 重读。写操作主动等待刷新，不押注 watcher 正好及时到达。关闭 watcher 要等待原生 handle/callback 释放；作用域切换释放旧监听，断线有界退避重连。

```text
t0 缓存 src/retry.ts = 内容 A
t1 Agent 改成 B，通知可能合并/延迟
t2 用户查看 -> 读取当前文件 B
t3 文件又变 C，旧读取响应不能串入另一个 Workspace 的缓存
```

当前没有 file_tree、search_index、diff SQL 表。文本读取先做大小预检，再拒绝二进制/无效 UTF-8；metadata 大小门槛不是流式硬上限。搜索有时间、字节和结果数量预算，fixed-string/smart-case 与参数分隔避免把用户文字当命令参数或正则。

**可能方案**：若要回看“当时文件”，保存内容摘要和不可变快照，或明确引用 Git blob。新增 blob 存储、来源版本及保留策略，成本是磁盘/隐私；快照缺失标不可复现，不从当前文件补造历史。

## 四种 diff 范围为什么不能混着讲？

### 当前实现与数据演算

W1 的 `worktrees.base_commit_id=C100`，当前 HEAD=C101，index 为 I1，工作目录为 D1。Branch/Committed 范围需要保存的基线；Unstaged/Staged 对应当前工作目录与 index/HEAD 的差异。主工作区没有受管 Worktree 行时，没有该固定基线，因此只支持相应无基线范围。

| 观察对象 | 意义 | 容易错的说法 |
| --- | --- | --- |
| 固定 base_commit_id | 任务开始的比较基线 | “总是最新 main” |
| HEAD | 当前提交 | “包含未提交改动” |
| index | 将要提交的暂存集合 | “等于刚才 UI 全部 diff” |
| 工作目录 | 当前文件 | “已经全部暂存” |

当前 stage/unstage 按路径，空路径列表有“全部”的语义；commit 只提交当前 staged 集合。存在 Worktree 行时，变更前核对路径与记录分支；项目主 checkout 无这份受管记录，就操作当前 checkout，不能声称同样固定了分支。

### 连续追问：看完 diff 后 index 又变了怎么办？

**边界与缺口（推理边界）**：Git 操作成功证明它提交了操作当刻的 index，不自动证明等于用户几秒前看到的 diff。共享使用租约防后台清理，不阻止所有外部 Git 程序。

**可能方案**：展示审查快照摘要（HEAD、index tree、路径集合），提交带 expected_index_digest，变化时拒绝并要求重看。新增审查票据或请求字段，成本是额外比较；校验与提交之间还要在同一受控 Git 操作边界保护，外部无法完全隔离时明确剩余竞争，不能检查完再无锁等待。

## 文件引用为什么不能总是还原发送时的内容？

普通引用传 `path:range` 供 Agent 读取，UI 显示 chip；diff 引用会展开小 patch。前者不是当时文件正文快照，文件改动后行号可能偏移；后者保存具体差异片段但仍不等于整个仓库快照。

演算：发送时 retry.ts 第 10 行是 `limit=2`，Agent 读取前已改到 `limit=5`。历史里只有路径范围时无法证明它看见哪一个。**可能方案**：引用带 commit/blob 或内容摘要与必要片段，记录解析时刻；代价是内容存储与权限控制，摘要不匹配提示漂移，不静默把新内容当旧输入。

## 完整业务推演：审查期间删除任务

W1 被打开审查，Git 操作持共享使用租约；删除业务对象提交清理 job，物理清理需要独占租约并核对所有权，因此不能在已接入的 Git 操作中途直接移除目录。普通文件读取未全面加入该租约，仍可能遇到不存在并应明确失败。PTY 基础组件没有 terminal_history 表，也不自动拥有永久输出回放；文件/终端/聊天历史是三个数据系统。
