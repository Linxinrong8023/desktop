> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

学习创建隔离 Git 工作目录、预留资源、失败补偿与后台清理。

## 设计逻辑与执行流程

当前 Task 总是对应隔离的 Git worktree，不是所有聊天的必需父对象。

1. 选择本地 base ref，解析为不可变 commit ID；申请独立 Task／Workspace ID。
2. 检查目录及 `ora/<prefix>` 分支冲突；通过 provisioning lease 记录在途资源，避免未完成创建与清理互相干扰。
3. Git 创建 worktree 后记录 workspace 位置、worktree 基线以及 task 标题。数据库后续失败时尝试补偿软删除与 Git 清理。
4. 删除任务时，在同一数据库删除事务登记清理 job；后台 worker 再处理真实目录／分支，不在 SQLite 写锁中运行 Git。
5. 清理根据结果推进 `pending → completed`，或进入 `manual_attention`；失败次数和下一次时间可以跨重启保存。

创建时用配置根目录构造新路径，访问已有任务时用保存的位置证据。修改默认根目录不意味着旧任务目录自动搬家。

## 数据库表与持久化

| 表 | 保存什么 | 写入时机 |
| --- | --- | --- |
| `tasks` | `id,workspace_id UNIQUE,title,is_deleted` | 最终用户可见任务及重命名／软删除 |
| `worktrees` | `workspace_id,branch_name,base_commit_id,is_deleted` | 创建后的 Git 基线与关联 |
| `workspaces`、`workspace_locations`、`workspace_provisioning` | 执行归属、真实位置、准备状态 | 预备及结果落地 |
| `worktree_provisioning_leases` | 工作区、仓库、checkout、branch、`lease_expires_at` | 在途创建资源的持久租约 |
| `git_cleanup_jobs` | 同样的资源证据，外加 `state,attempts,next_attempt_at,last_error` | 删除事务登记，worker 更新 |
| `user_config` | `worktree_root` | 修改新建工作树的默认根目录 |

Git 的提交对象、索引和工作目录在文件系统，表不保存整个代码副本。两个清理／租约表没有指向业务表的外键，允许业务记录不可见后继续保留清理证据。

## 目前存在的缺陷与限制

- **已确认的限制**：创建依赖有效本地 Git 仓库和可解析的 ref，不能把非 Git 目录作为这种 Task 的 worktree。
- **已确认的限制**：数据库事务不能涵盖 Git 操作；补偿也可能失败，需观察 `git_cleanup_jobs`，不能承诺删除接口完成时磁盘一定已释放。
- **设计风险**：用户或外部进程修改 checkout／branch 后，清理必须依赖身份检查，不能直接按旧路径递归删除。
