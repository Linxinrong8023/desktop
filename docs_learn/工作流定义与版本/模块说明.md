# 工作流定义与版本

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

理解工作流草稿、发布快照、回滚与实际执行版本的关系。

## 设计逻辑与执行流程

创建 Workflow 同时创建初始 draft，repository 事务保证两者一起出现。draft 更新原位改图，不每次编辑新建版本。

- Publish：复制 draft 为不可变发布快照，并在一次事务切换 published 指针。
- Rollback：把历史图复制回 draft，不自动切换当前 published 指针。
- Activate：选择历史快照为 published，并同步它的图到 draft。
- 删除 Workflow 软删除其快照；不允许单独删除 draft 或当前激活版本。

CRUD 层负责记录和版本业务；图结构检查、运行前能力验证和执行是独立阶段。运行时依据 Run 的 snapshot_id，不能读取此刻已被用户编辑的 draft 来解释旧执行。

## 数据库表与持久化

| 表 | 关键字段 | 写入时机 |
| --- | --- | --- |
| `workflows` | `id,namespace,name,published_snapshot_id,is_deleted` | 创建、重命名、发布／激活、软删除 |
| `workflow_snapshots` | `id,workflow_id,version,graph,created_at,updated_at,is_deleted` | 创建 draft、原位编辑、发布新快照 |
| `workflow_runs` | `workflow_id,snapshot_id` | 启动运行时固定定义与版本引用 |

`graph` 是 TEXT 中的 JSON，包含节点、边、节点配置等。表没有单独的 workflow_nodes／workflow_edges；不能用 SQL 外键检查图中的边。未删除 `(workflow_id,version)` 唯一。

`published_snapshot_id` 当前未声明 SQL 外键，由 repository 事务和业务验证保持正确；与 `workflow_snapshots.workflow_id` 的物理外键要区分。

## 目前存在的缺陷与限制

- **已确认的限制**：draft 能保存不代表图可执行，未知节点／环／能力不支持要在图解析或 start 阶段报错。
- **已确认的约束缺口**：发布指针不是数据库外键，手工 SQL 可制造悬空或错属引用，不能绕过 repository。
- **设计边界**：graph JSON 的内部结构不由数据库逐节点约束；演进节点合同需要同时考虑历史快照的解析。
