## 模块职责

理解 Agent Runtime、Supervisor、Session Actor、共享 ACP 连接及故障隔离。

## 设计逻辑与执行流程

所有 Agent 来自已安装 Agent 插件。`AgentRuntimeManager` 按完整 `namespace/name` 的 AgentRef 管理独立 Supervisor；一个 Agent 下的多个 Session 共用 ACP 进程与连接，每个 Ora Session 用 Actor 串行处理命令。

准备连接有三道确认：插件 `ora/register` 合同完整；`agent/start` 成功并确认协议；ACP 初始化成功。插件 Lifecycle 拥有 Deno 插件进程，插件再拥有 Agent CLI；Runtime 借用连接，不直接搜索 PATH 或启动 CLI。

一次 prompt：定位 Actor → 准备／恢复 provider Session → 写用户历史 → 发送 ACP → 路由流事件 → Actor 组装并记录 → 消费对应响应 fence → 完成本轮。相同 Session 只允许一个 prompt owner，其他打开视图可以跟随。

路由使用 provider Session ID 与 connection generation；旧 generation 事件会丢弃。连接级事件流有序但无界，Session FIFO 上限 256。独立控制通道保证终止事件不会被普通队列堵住。

三种 generation 必须分开：插件进程代次、ACP 连接代次、Effect 期望状态代次。Effect 引起 CLI 更新时不能假定所有代次同步变化。

启动将残留 Running 会话校正为 Stopped。单会话队列超限／超时主要影响该会话；连接损坏影响该 Agent 下已注册会话。Supervisor 独立退避，短时间连续异常会打开重启熔断。

## 数据库表与持久化

| 数据 | 存储位置 | 保存责任 |
| --- | --- | --- |
| 当前 Agent 绑定与 provider Session ID | `sessions.agent_cli,agent_session_id` | Session repository；创建／切换／重建确认时写入 |
| 注册状态、历史写入降级 | `sessions.status,history_degraded_reason` | Runtime 推进生命周期时更新 |
| 对话事件 | Ora history JSONL | Session Recorder |
| Supervisor、Actor、路由、重试计数、连接 generation、pending 权限 | 内存 | 进程重启后重新建立 |
| 插件能力交付与 readiness | `effect_*` | Effect 模块；不能替代 Runtime 当前连接状态 |

没有 `agent_runtime`、`connections` 或运行进程表；`agents` 表只是可配置角色定义。`sessions.status=0` 表示 Running（已注册连接），不代表此刻正在生成内容。

## 目前存在的缺陷与限制

- **已确认的安全限制**：活动 prompt 中权限请求会自动授予，当前不是逐工具人工审批模式；界面上的偏好不能当作执行沙箱。
- **已确认的资源风险**：连接级流无界，单 Session 有界不能证明整个链路内存有界。
- **已确认的恢复限制**：一分钟内超过三次异常会熔断，该进程余下时间不再自动重试；缺少本地 CLI 属于可重试 unavailable，而坏包／缺合同属于终止性失败。
- **已确认的能力边界**：退出与卸载回收运行资源，不会清掉 provider 自己的历史库。
