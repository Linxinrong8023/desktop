# 插件安装与生命周期

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

把插件包、来源身份、运行进程和运行能力分开，理解安装与热更新如何影响 Agent。

## 设计逻辑与执行流程

安装先解析 `orax.toml`，再验证真实包结构、入口及路径。`ora-plugin-manifest` 负责声明合法性，`ora-plugin-manager` 负责磁盘事实，验证后的 `InstalledPlugin` 携带类型化 contribution。

来源 namespace 由宿主根据市场来源确定，不接受包自报身份。完整 PluginId 是 `namespace/name`，AgentRef 用统一转换规则得到同一包的持久身份；两个来源同名包不能共用一个 Supervisor。

Agent 和 Workbench 使用通用 Deno 插件进程；Skill／Webview／MCP／Hook 不因此必须启动 `main.js`。MCP／Hook 在被使用时仍可能涉及自己的外部执行能力。

`ora-plugin-lifecycle` 是插件进程唯一所有者；`ora-plugin-runtime` 实现通信／执行机制。插件 `ora/register` 声明真实运行合同。Running 表示进程在运行，不证明 Agent 已通过 ACP 准备阶段。

安装、卸载、scan 经过 Backend Plugin API 后协调 Agent 集合及相关资料投影；Runtime 能感知热安装，不要求每次重启。配置、技能或 MCP 刷新分别走对应业务协调路径。

## 数据库表与持久化

| 表／介质 | 保存内容 | 何时更新 |
| --- | --- | --- |
| `plugin_marketplace_source` | `url,branch,use_proxy,position,enabled,artifact_retrieval` 与时间 | 添加／编辑／禁用／排序来源 |
| `plugin_source_namespace` | `canonical_url → namespace` 的唯一绑定 | 为来源分配身份，删除来源配置也不丢弃该绑定 |
| 安装目录 | 版本化包代码、`orax.toml`、assets | 安装／升级／卸载 |
| 插件私有数据目录 | `store.json` 与插件私有资料 | 配置保存及插件自身操作 |
| `skills`、`effect_sources`／`effect_revisions` 等 | 可用技能目录与交付源投影 | 插件技能发现／协调 |
| Lifecycle／registry 内存 | Running 状态、进程 generation、注册方法 | 当前进程存活期间 |

没有 `installed_plugins` 或 `plugin_processes` 表。安装事实来自包目录扫描；删除来源行不等于删除已安装包。`artifact_retrieval` 从 0009 起保存带 type 的获取配置，不是凭字段名猜测“永远直接下载”。

## 目前存在的缺陷与限制

- **已确认的限制**：包验证只说明符合宿主合同，不等于不可信插件已被强隔离；运行权限需要按当前启动能力评估。
- **已确认的限制**：无通用进程的静态贡献显示 stopped 不能当作不可用；Agent 的 Running 也不能当作 Ready，UI／诊断需区分。
- **已确认的持久身份约束**：namespace 会进入磁盘路径、技能目录行和 Effect Consumer 身份，不能为“重装方便”随意重分配。
- **设计风险**：包文件、来源配置、目录投影分别更新，磁盘被外部改动时需重新扫描与协调，SQL 不会自动发现。
