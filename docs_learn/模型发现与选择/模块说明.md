# 模型发现与选择

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

区分会话创建前的模型目录、当前会话的可选模型合同和用户偏好。

## 设计逻辑与执行流程

有两条模型发现路径：创建前通过插件 `agent/list_models`（携带当前工作区目录）；创建后使用 ACP Session 握手返回的 config options。

- 创建前模型查询按插件独立超时，汇总成功组；模型可能随工作区及插件状态变化。
- Runtime 不缓存共享连接上的预会话目录，因为 Effect 可让插件重启 CLI，而连接 generation 不一定变化。
- 用户选中模型是意图。`startSession`／`switchSessionAgent`／首次 attach 的 prompt 将意图带到新会话，按那次握手的真实选项校验和应用。
- 已 attach 的 Session 使用自己的 config options 进行配置；不能拿目录查询结果覆盖会话权威选项。
- 有些 Agent 只通过 ACP Session 提供模型选项，它们的预会话目录为空也不代表没有模型。

## 数据库表与持久化

| 数据 | 位置 | 何时保存 |
| --- | --- | --- |
| 各 Agent 上次偏好模型 | localStorage 中 agent-model-preference store | 用户选择时，按完整 AgentRef 记录 |
| 未创建／待切换会话的模型意图 | pending-agent store 内存 | 点选后暂存，实际应用后清除 |
| 当前 config options／实际配置 | Actor 与 provider Session | 握手、配置响应更新；生命周期由 provider 管理 |
| 会话 Agent 归属 | `sessions.agent_cli,agent_session_id` | 创建／换绑 |

当前 `sessions` **没有 `model` 或 `model_id` 列**，也没有独立 models 表。不能从 SQLite 会话行查询每轮实际用了什么模型。配置角色 `agents` 同样不是模型目录表。

## 目前存在的缺陷与限制

- **已确认的限制**：预会话查询只返回成功组，失败 Agent 可能表现为缺失；诊断要看对应 runtime 状态和日志。
- **已确认的限制**：localStorage 是当前客户端偏好，清除存储或换客户端会丢失；历史值可能不在最新目录中，需要实时校验。
- **设计缺口**：当前没有按轮持久化模型审计表，不能保证重建“某轮实际用的模型”；若业务需要成本／模型审计，需另行设计，不能假称已实现。
