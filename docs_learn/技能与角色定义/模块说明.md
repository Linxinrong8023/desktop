> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

学习可复用 Skill 包和配置角色的管理，区分它们与真正运行的 Agent。

## 设计逻辑与执行流程

Skill 是供执行者读取的资料包，通常包含 `SKILL.md` 和附属资源。角色 AgentDefinition 是可配置的说明内容，既不是 Agent CLI，也不是 Runtime Supervisor。

本地 Skill 创建／导入／更新／删除需要同时处理目录和目录表：暂存包 → 写 Prepared journal → 切换正式目录 → 标记 Swapped → 写数据库行 → 清理 journal 与备份。失败通过 journal 和 backup 恢复；不在持有 SQLite 事务锁时做慢速文件重命名。

包根下 `.ora-staging`、`.ora-backup`、`.ora-journal` 为保留目录。名称校验拒绝点开头，避免技能名与事务目录碰撞。恢复使用不可变 skill ID 和之前的行版本，而非只看可重用的名称。

列出 Skill 时实时评估 package availability；目录丢失或根 SKILL.md 不可解析会显示 unavailable，不直接删除表行。同名 unavailable 本地技能可通过创建／导入恢复原 ID。插件 Skill 的来源身份由 namespace 区分，实际交付到工作区由 Effect 完成。

## 数据库表与持久化

| 表／文件 | 保存内容 | 写入责任 |
| --- | --- | --- |
| `skills` | `id,namespace,name,description,created_at,updated_at,is_deleted` | Skill CRUD、插件技能投影 |
| 本地 `<app_data_directory>/atoms/skills/<name>` | SKILL.md 正文、附属文件 | FilesystemSkillStorage |
| `.ora-journal`／`.ora-backup`／`.ora-staging` | 在途包操作及补偿资料 | 修改前建立，提交后清理，启动时恢复 |
| `agents` | `id,namespace,name,description,content,created_at,updated_at,is_deleted` | AgentDefinition CRUD／导入 |
| `effect_sources`／`effect_revisions` | 交付源和不可变版本定义 | 技能源协调；选择与实际落地参见 Effect 模块 |

`skills` 不存 Skill 正文；`agents.content` 存角色内容。两张表都用未删除 namespace＋name 的大小写不敏感唯一索引。Session 的 `agent_cli` 不外键引用 `agents.id`。

## 目前存在的缺陷与限制

- **已确认的限制**：文件与表的原子性依靠 journal／恢复，不是数据库天然跨文件事务；直接改目录绕过协议会导致 unavailable 或恢复冲突。
- **已确认的耐久性边界**：Windows 目录同步是 best effort；macOS sync_all 不是 F_FULLFSYNC；SQLite NORMAL 也有断电窗口。
- **已确认的模型边界**：创建一条 agents 角色记录不会安装 Agent、发现模型或建立 ACP；角色可配置与执行能力可用是两项检查。
