main.js 启动后，Ora 怎么知道它会什么？

Manifest 说明磁盘包是什么类型；ora/register 则由已经启动的进程声明“这一代进程实际实现了哪些调用和通知”。

Agent 插件进程会声明什么

{
  "method": "ora/register",
  "params": {
    "methods": [
      "agent/start",
      "agent/stop",
      "agent/listModels"
    ],
    "emits": ["agent/acp"],
    "effectSurfaces": []
  }
}

methods 表示 Ora 可以 request/invoke 的方法；emits 表示插件可以主动发出的 notification；effectSurfaces 是可选的 Agent Skill 消费目录声明。这里的声明者是运行 main.js 的 Deno 插件进程，不是真实 Agent CLI。

为什么必须先注册再使用

如果 Ora 不先检查合同，只在用户发送第一条 prompt 时才发现插件没有 agent/acp，错误就会发生在真实用户操作中。

现在合同会在连接建立时整体检查。缺少 start、stop、listModels 或 emitted agent/acp 的 Agent 插件会直接进入失败状态，不会等到某个会话运行一半才暴露。

为什么注册后不能修改

一代进程只允许发送一次 ora/register。如果运行中随意增删能力，Host 的调用许可、notification 白名单和消费者假设会在并发请求中突然变化，很难确定某条消息到达时合同是什么。

需要改变合同，就启动新的一代插件进程，重新注册一份完整快照。第二次注册本身是协议错误。

注册不等于信任插件自称：Plugin Runtime 解析注册，Lifecycle 做通用 kind 规则检查，而 Agent runtime 的 plugin_agent adapter 还会验证完整 Agent 合同。只有全部匹配，才调用 agent/start。

面试表达：每个插件进程在启动时通过唯一且不可变的 ora/register 声明 methods、emits 和可选 Effect surfaces。Host 在任何会话开始前校验注册与安装 kind 的合同一致性；运行中改变能力必须通过新 generation，而不是原地修改注册。
