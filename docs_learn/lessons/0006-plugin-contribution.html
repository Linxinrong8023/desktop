Lesson 0006 · Contribution

这个插件到底贡献什么能力？

Manifest 中的 kind 是插件自己的字符串声明；验证完成后的 PluginContribution 是 Ora 内部可以直接使用的类型化结果。

Contribution 是什么意思

Contribution 可以理解为“这个插件给 Ora 增加的能力”。Agent 插件贡献一个可连接的 Agent；Skill 插件贡献一组 Skill；Webview 插件贡献一个可展示的远程页面能力。

它不是又一份 Manifest，而是 Manager 检查完 Manifest 和磁盘文件后整理出的结果。

为什么使用 enum

Rust 的 enum 可以先理解成一个“只能六选一的盒子”。每个 InstalledPlugin 恰好装入下面一种 contribution，并随身携带该类型专属的数据。

PluginContribution
├── Agent(已验证的 main.js 入口)
├── Workbench(入口 + 页面资源)
├── Webview(已验证的页面描述)
├── Skill(已解析的 Skill 列表)
├── Mcp(已编译的 MCP 描述)
└── Hook(已验证的 Hook 描述)

布尔开关不是不能用，而是允许矛盾状态

下面这种内部结构能够工作，但它把正确性留给程序员手动维护：

struct LoosePlugin {
  is_agent: bool,
  is_skill: bool,
  agent_data: Option<AgentData>,
  skill_data: Option<SkillData>,
}

一个合法 Agent 应该是 true / false / Some / None。但同一个结构也允许造出以下值：

// 声称是 Agent，却没有 Agent 必需数据
is_agent = true
agent_data = None

// 同时声称是两种插件
is_agent = true
is_skill = true

// 不是 Agent，却带着 Agent 数据
is_agent = false
agent_data = Some(...)

这些值可以进入内存并通过函数参数传递；只有运行到手写的检查代码时才会报错。如果某个调用点忘记检查，就产生 bug。

即使只保留一个 kind: PluginKind，再配多个 Option，仍然可能出现 kind = Agent 但 agent_data = None。所以问题不只是“类型标签会不会重复”，还包括“标签与专属数据是否永远一致”。

Contribution enum 则只允许直接构造完整的合法形状：

enum PluginContribution {
  Agent(AgentData),
  Skill(SkillData),
}

选了 Agent 就必须同时交出 AgentData；同一个 enum 值也不可能同时选择两个 variant。检查从“运行时靠人记得写”变成“编译时由类型保证”。

输入与输出：kind = "agent" 是待验证的输入；PluginContribution::Agent(...) 是验证后的输出。

为什么 Contribution 不直接替代 TOML 的 kind

因为它们不在同一层。kind 是磁盘文本中的一个字段；PluginContribution 是 Rust 程序在内存中构造的数据。完整转换是：

TOML: kind = "agent"              插件自己的文字
          ↓ Manifest 解析
PluginKind::Agent                 只有类型标签
          ↓ Manager 检查 main.js
PluginContribution::Agent(
  InstalledPluginAgent { entrypoint }
)                                 类型 + 已验证专属数据

把 TOML 字段从 kind 改名为 contribution，它仍然只是一个待验证的字符串。真正的差别不在字段叫什么，而在 Manager 能否把“Agent 标签”和“已经验证的 Agent 入口”绑定成一个不可矛盾的内部值。

同样，多个布尔开关的反例是在说明一种能运行但容易产生非法状态的内部结构，不是说当前 TOML 会出现多个字段。当前 TOML 用唯一的 kind 本来就不会遇到多类型声明问题；enum 解决的是解析完成之后，Rust 内部的标签与数据一致性。

面试表达：Plugin Manager 不把 kind 保留成一个裸字符串加若干可选字段，而是构造封闭的 PluginContribution 枚举。每个 variant 携带该 kind 已验证的专属 descriptor，因此一个 InstalledPlugin 恰好贡献一种能力，非法字段组合无法进入后续系统。
