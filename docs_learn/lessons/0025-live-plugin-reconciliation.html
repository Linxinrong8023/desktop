Lesson 0025 · Live Reconciliation

不重启 Ora，Agent 插件怎样加入和离开？

动态插件系统不能只把文件写入磁盘，还必须让当前 Ora 进程里的 Lifecycle 快照与 Supervisor 集合同步变化。当前实现用显式 scan 与 sync_plugin_agents() 完成这次协调。

安装：先进入 Lifecycle，再进入 Agent Runtime

Installer 写入并验证插件包
  ↓
Lifecycle scan 刷新 InstalledPlugin 快照
  ↓
Backend 调用 sync_plugin_agents()
  ↓
发现新的 AgentRef
  ↓
创建新的 ConnectionSupervisor
  ↓
Supervisor 尝试建立 Ready connection

如果只完成落盘而没有后两步，设置页可能显示“已安装”，但当前 Agent Runtime 仍找不到它，用户必须重启 Ora。显式同步就是为了消除这段不一致。

更新：身份不变，两种 generation 更新

更新插件时，Lifecycle 会先停止正在使用旧代码的插件进程，再替换安装版本并重新扫描。AgentRef 和 PluginId 通常不变，所以 Supervisor 仍代表同一个 Agent；旧 connection 断开后，它会从新插件代码建立新的 Plugin process generation 与 Agent connection generation。

同一个 AgentRef / PluginId
旧版本：Plugin generation 5 → Connection generation 2
更新并重连
新版本：Plugin generation 6 → Connection generation 3

卸载：从安装集合和 Supervisor 集合同时移除

关闭插件拥有的 UI surface
  ↓
停止当前插件进程与受管子进程树
  ↓
暂存并移走 installed 代码
  ↓ 可选删除或保留 data
从 Lifecycle 已安装快照移除
  ↓
清理 Skill / Effect 投影
  ↓
sync_plugin_agents()
  ↓
从新请求可见的 Supervisor map 移除

Session 数据不会因为插件卸载而删除，它仍保存原来的 AgentRef。之后再使用时会得到 agent_runtime_unavailable，重新安装相同 Agent provider 后才可能恢复。

已有 actor clone 的细节：从 Supervisor map 移除不会仅凭一次 map 删除就粗暴销毁其他模块已经持有的 Supervisor handle；但卸载流程已经停止底层插件进程，所以这不代表旧会话还能继续正常对话。它只是让持有者通过既有对象观察 connection 丢失与 unavailable，而不是撞上悬空引用。

stop 不是 disable

当前 API 有 stop_plugin 和 activate_plugin，但没有持久化的插件 enabled/disabled 状态。

stop_plugin
  → 当前 Plugin generation 停止
  → 插件仍在 InstalledPlugin 集合
  → Agent Supervisor 仍存在
  → Supervisor 为维持 Agent connection，可能再次 ensure_running

因此，对一个正在被 Supervisor 管理的 Agent 插件，stop 更接近一次暂时停止或手动重启触发点，不能承诺“以后都不要启动”。如果产品需要真正的禁用功能，必须增加持久化 enabled 状态，并让插件发现、Supervisor 同步和自动重试共同尊重它。

当前实现边界：不要在面试中说“禁用后 Supervisor 静默重试”。当前没有正式 disable 操作；如果未来新增 disable，正确语义反而应该是 Supervisor 不再重试，而不是一边禁用一边重新启动。

谁负责哪一段？

模块负责的变化
Installer / Manager代码落盘、包结构验证、版本替换
Plugin LifecycleInstalledPlugin 快照、进程停止、scan、卸载事务
Backend Plugin API清理 Skill/Effect 投影并编排同步顺序
ConnectionSupervisors把已安装 Agent 集合协调成 Supervisor 集合
Session保留 AgentRef 和历史，不因插件暂时缺失而损坏

面试表达：插件安装、更新、扫描和卸载完成后，Backend 都显式调用 sync_plugin_agents，把 Lifecycle 的 InstalledPlugin 快照协调成按 AgentRef 索引的 Supervisor 集合。安装会在当前进程创建新 Supervisor；更新保持身份但滚动进程和 connection generation；卸载先关闭 surface、停止进程树并移除包，再移除新请求可见的 Supervisor，而 Session 仍保留 AgentRef。当前只有临时 stop/activate，没有持久 disable；真正禁用必须进入 desired state 并阻止 Supervisor 自动重启。
