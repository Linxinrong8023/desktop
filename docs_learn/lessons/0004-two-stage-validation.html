Lesson 0004 · Validation

为什么插件要过两道检查？

Manifest 写得合法，不代表磁盘上的插件包真的符合声明。Ora 把这两类问题分给两个模块。

第一道：检查“身份证写得对不对”

ora-plugin-manifest 接收 orax.toml 的文本，检查语法、必填字段、kind 拼写、版本格式，以及不同字段能否合法组合。

它不访问磁盘，所以不知道 main.js 是否真的存在。就像证件审核员只检查申请表本身，不能隔空检查箱子里的货物。

第二道：检查“箱子里是否真有对应货物”

ora-plugin-manager 已经知道插件包在磁盘上的位置。它根据通过第一关的 kind，检查实际文件和宿主规则。

例如：Agent 和 Workbench 必须有 main.js；Workbench 还必须有页面；Skill 必须有一个或多个 assets/<name>/SKILL.md。

orax.toml 文本插件自己的原始声明。
Manifest 验证文本结构与字段组合是否合法。
Manager 验证声明与磁盘文件、宿主规则是否一致。
InstalledPlugin两关通过后得到的可信宿主视图。
关键边界：Manifest 模块不负责读取文件系统，Manager 也不重新发明 TOML 语法校验。两者各自只拥有自己能可靠判断的事实。

面试表达：Ora 把插件验证分为 schema 验证和 host-side package 验证。Manifest crate 把不可信文本解析成满足字段不变量的结构；Plugin Manager 再结合磁盘和插件 kind 校验入口、资源与禁止项，最终生成可信的 InstalledPlugin。
