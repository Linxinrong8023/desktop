Lesson 0005 · Trusted View

两关通过后，Ora 得到什么？

Ora 不会让后续每个模块重新阅读 Manifest、重新检查文件。Plugin Manager 把验证结果整理成一个 InstalledPlugin。

从“申请材料”变成“已核验档案”

原始插件包和 orax.toml 像申请人自己提交的材料，内容还不能直接信任。

InstalledPlugin 像审核机构签发的档案：身份、版本、包位置和能力类型已经经过两道检查，后续模块可以按这份档案办事。

Package磁盘上的原始插件文件。
Manifest解析并验证插件自己的声明。
Manager验证声明与实际包内容一致。
InstalledPlugin提供给后续模块的宿主可信视图。

里面包含什么

InstalledPlugin
├── package_root   已验证插件包的位置
├── id             namespace/name
├── version        已验证版本
├── metadata       名称、描述、主页等
└── contributes    已验证的能力类型和专属信息

例如 Agent contribution 内已经带有验证过的 main.js 相对路径；Skill contribution 内已经带有解析过的 Skill 列表。后续消费者不必再靠 kind 字符串猜文件结构。

“可信”有范围：这里只表示结构、路径和 kind 规则已经通过宿主验证，不代表插件代码一定没有恶意或运行时永远不会失败。运行安全和故障隔离是后面的层次。

面试表达：Plugin Manager 把不可信的包和声明收敛为 InstalledPlugin。它携带经过验证的身份、版本、包根和类型化 contribution，让 Lifecycle 与各类消费者依赖已建立的不变量，而不必重复解析 Manifest 或检查包布局。
