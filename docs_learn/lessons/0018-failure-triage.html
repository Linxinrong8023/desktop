Lesson 0018 · Failure Triage

失败不是一种失败

Supervisor 不能遇到任何错误都无限重试，也不能一失败就永久放弃。它先判断失败属于哪一类，再决定状态、重试和影响范围。

类比：电话为什么打不通？

号码对应的手机还没买：这是预期的环境缺失。过一会儿再试，有一天用户买好手机就能接通。

电话偶尔断线：可能只是临时故障，可以重拨；但一分钟连续断四次，就不能无限骚扰系统。

双方根本不说同一种协议：重拨一万次也不会突然听懂，必须升级插件或宿主。

这正好对应 Ora 的三类 Agent 故障：预期缺失、异常但可恢复、确定性不兼容。

第一类：预期缺失

典型情况包括：

  • 插件暂时不存在、被禁用，Lifecycle 无法提供插件进程；
  • 插件能够启动，但它包装的 Agent CLI 没安装；
  • agent/start 返回专门的 AGENT_NOT_INSTALLED = -32001。
状态：Unavailable
日志：不反复警告
重试：持续重试，不计入 crash circuit
节奏：250ms → 500ms → 1s → ... → 最长 30s

为什么不直接 Failing？因为“没安装”是正常配置状态。用户稍后安装 CLI 或重新启用插件后，Supervisor 应自动恢复，不要求重启 Ora。

第二类：异常但可能恢复

例如普通的 agent/start 错误、模型发现失败、ACP initialize 超时，或者已经 Ready 的 connection 突然断开。

偶发错误值得重试，但频繁错误可能形成 crash loop。因此 Ora 记录最近一分钟的真正故障：

当前熔断规则：一分钟内前三次真正故障仍允许下一次尝试；第四次故障打开 restart circuit，状态变为 Failing，本次 Ora 进程中停止自动重试。

这里说“第四次失败”，不是“最多启动四次”。超过一分钟的旧失败会移出窗口；一次成功连接也会把退避间隔重置到 250ms。

第三类：确定性不兼容

例如 Agent 插件没有注册完整合同：

缺少 agent/start / agent/stop / agent/listModels
缺少 emitted agent/acp
返回了宿主不支持的 ACP major version

这不是“今天运气不好”，而是当前插件代码与当前宿主合同不兼容。同一个包原样启动多少次都会得到相同结果。因此：

状态：Failing
重试：立即停止
恢复：更新插件或宿主，再建立新的运行环境

失败会炸掉多大范围？

Session 自己超时、取消或队列溢出：只停止这一个 Session，不重启共享 Agent。

ACP framing、correlation、stdio 或 connection 失败：这一代 connection 已不可信，停止这个 Agent 上注册的 Session，回收 generation 后重连。

某个 Agent 进入 Failing：其他 Agent 各有自己的 Supervisor，仍然正常工作。

这叫故障隔离：错误发生在哪一层，就尽量只让那一层及其真正依赖者失败，避免把整个 Ora 一起拖垮。

面试表达：Ora 不把所有 Agent 启动失败一概处理。CLI 未安装属于预期配置，发布 Unavailable 并静默持续退避；普通启动或连接故障会清理旧 generation、计入一分钟滑动窗口并重试，第四次故障熔断为 Failing；合同缺失或 ACP 版本不兼容是确定性错误，立即 Failing。Supervisor 按 Agent 独立运行，所以一个 Agent 故障不会拖垮其他 Agent。
