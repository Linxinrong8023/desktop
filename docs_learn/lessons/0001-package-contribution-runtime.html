插件到底是什么？

这一课只学一个概念：插件是一个可以后来安装、用来给主程序增加能力的独立组件。

先把 Ora 想成一部手机

Ora 主程序像手机系统，负责窗口、任务、会话这些共同能力。

插件像后来安装的 App。装地图 App，手机多了导航能力；装音乐 App，手机多了听歌能力。

手机系统不必提前把全世界所有 App 都写进自己里面。它只要规定好：App 怎样安装、能使用什么能力、怎样与系统交流。

“内置”与“插件化”的区别

以前：内置想支持 Agent A，就把 Agent A 的接入代码直接写进 Ora。
遇到变化想再支持 Agent B，通常还要修改、测试并重新发布 Ora。
现在：插件化Ora 先规定统一的“插口规则”，具体 Agent 的接入放到独立插件里。
以后扩展安装一个符合规则的新插件，就能增加新的 Agent 能力。
一句话定义：插件是在主程序之外独立提供、可以按约定接入主程序，从而增加某种能力的组件。

Agent 插件不是“大模型本身”

在 Ora 里，Agent 插件更像一只转换插头：一头符合 Ora 规定的插口，另一头连接某个具体 Agent 程序。它让 Ora 能使用这个 Agent，但插件本身不等于模型，也不等于整个 Ora。

Ora 主程序  ←  统一插口  ←  Agent 插件  ←  具体 Agent 程序

这里先不用理解“统一插口”内部怎么实现。后面的课会把它拆成文件、程序、进程和通信规则，一个一个学。

为什么值得插件化

核心原因是把“稳定的主程序”和“经常增加或变化的具体能力”分开。这样新增 Agent 时，理想情况下只增加或更新对应插件，不必反复修改 Ora 主程序的核心代码。

最初级的面试说法：插件系统让主程序先定义稳定的接入规则，再把具体能力放在可独立安装的插件中。这样新增一种 Agent 能力时，可以主要新增插件，而不是把每个 Agent 的特殊逻辑都继续写进 Ora 主程序。
