Lesson 0007 · Runtime

插件贡献能力，不等于一定启动进程

PluginContribution 回答“它提供什么”；Plugin Runtime 回答“是否需要运行一个长期通信的 main.js 进程”。

继续用手机 App 类比

一套离线壁纸安装后就能被系统读取，不需要一直运行一个壁纸程序。

聊天 App 则需要运行，才能持续接收和发送消息。同样，不同插件贡献能力的方式不同，不能认为“只要是插件就必须有进程”。

Ora 当前的六种 contribution

类型通用 Deno Plugin Runtime直观原因
Agent需要main.js 要与 Ora 长期双向通信，并连接具体 Agent
Workbench需要main.js 为工作台页面提供调用能力
Skill不需要宿主读取并注册包内的 Skill 文件
Webview不需要宿主根据已验证描述展示远程页面
MCP不需要当前贡献的是已验证 transport 描述，不运行通用插件进程
Hook不需要当前贡献的是 Hook 描述与可执行物，不运行通用插件进程
措辞要准确：这里的“不需要进程”特指不启动 Ora 的通用 Deno Plugin Runtime。MCP 或 Hook 的后续消费者可能使用命令或可执行物，但那不是 Lifecycle 为该插件维持的 main.js 进程。

Skill 与 Effect 的关系

Skill 插件本身贡献静态文件。Backend 会把已验证的 Skill 元数据同步进共享目录与 Effect source；Effect Worker 再按照 Workspace 的 Desired 状态，把选中的 Skill 物化到 Agent 插件声明的 Skill surface，例如 .agents/skills。

Effect 负责的是交付与安全更新：复制哪些 Skill、目标目录当前是否一致、Agent 是否需要等待空闲和重启。它不读取 Skill 内容替 Agent 做决策，也不执行 Skill；最终由真实 Agent 从自己的发现目录读取并使用。

文档漂移：docs/effect-skill-state.md 仍写着没有 product worker 或真实 Agent 集成，但当前代码已有 effect_worker、Agent Effect surface 注册和 SDK coordination callbacks。学习以当前实现为准。

所以 stopped 不一定是故障

Lifecycle 只为 Agent 和 Workbench 管理通用插件进程。Skill、Webview、MCP、Hook 没有这种进程，因此它们即使已安装并可用，runtime 状态仍会显示 stopped。

已安装 / 可用     说明磁盘包通过验证
Contribution      说明插件提供什么能力
Runtime running   只说明通用插件进程此刻正在运行

面试表达：Ora 把安装可用性、贡献类型和运行时状态分开。只有需要持续双向通信的 Agent 与 Workbench contribution 进入通用 Deno runtime；Skill、Webview、MCP、Hook 由静态或专属消费者使用，所以已安装但 runtime 为 stopped 是正常状态。
