## 3. Loop、foreach Iteration 与执行作用域

| 编号 | 已落地措施 | 解决的问题与适用边界 |
| --- | --- | --- |
| WF-L01 | Loop 与 Iteration 分别建模：前者有跨轮反馈、`until` 和命名输出，后者逐项遍历数组并汇总。 | 不把两类不同循环混成含义不明的状态字段。 |
| WF-L02 | 校验容器所属关系、内部入口、跨域连线及选择器；拒绝不支持的嵌套复合结构。 | 防止内部节点绕过容器执行或读写其他作用域。 |
| WF-L03 | Loop 限制 1–100 轮，反馈从同一个本轮完成变量池读取。 | 避免无界执行以及反馈赋值顺序造成不同结果。 |
| WF-L04 | Loop 每轮保存独立执行作用域及子 NodeRun/Session；Iteration 通过节点记录的 iteration 区分轮次，推进经相应仓储事务提交。 | 同一节点定义在多轮复用仍保留独立证据，不覆盖历史。 |
| WF-L05 | 重跑轮换根作用域身份并保留旧历史。 | 旧轮回调不能误写新的执行。 |
| WF-L06 | Iteration 将 `item/index`、首批节点、轮次账本和后续推进按相应事务边界落盘。 | 重建引擎后从记录继续，不重复消费已完成轮次。 |
| WF-L07 | foreach 支持 `fail/continue`；输出统一为结果、逐项账本和失败数；空数组成功，超限明确失败。 | 失败策略不改变结果类型，也不静默截断输入。 |
| WF-L08 | 分支绕开结果收集节点时该轮失败；总览与 Theater 按轮展示“本轮未执行”。 | 不借用上一轮的变量、结果或会话制造成功。 |
| WF-L09 | 启动清扫识别被重启中断的子节点；失败续跑按容器清理轮次、账本、变量及后继，从第 1 轮开始。 | 防止残留活跃轮混入新尝试；不承诺从任意失败子节点继续。 |

## 5. Agent 接入、运行时与模型发现

| 编号 | 已落地措施 | 解决的问题与适用边界 |
| --- | --- | --- |
| AG-A01 | 以 ACP 统一 Agent 接入，使用完整插件 ID；每个 Agent 独立 supervisor 和连接。 | 屏蔽不同 CLI 差异，一个 Agent 故障不拖垮其他 Agent 或应用外壳。 |
| AG-A02 | 每 Session 串行 actor、跨 Session 并发，共享连接按私有 provider session ID 和 generation 路由。 | 保证单会话状态顺序，丢弃旧连接迟到事件，防止串话。 |
| AG-A03 | 首次发送才创建 provider session；创建期间用 guard，持久化或注册失败清理未暴露资源。 | 减少空会话，并覆盖异步创建的失败窗口。 |
| AG-A04 | 单一 prompt owner 与可跟随的 load 分开；load 读取 Ora 历史，不要求 Agent 在线。 | 查看历史不会抢占发送或取消权，也不无故启动 CLI。 |
| AG-A05 | 按需恢复 provider，先注册代际路由再 load，丢弃 provider 历史重放；必要时重建并延后提交绑定。 | 避免历史重复，降低恢复失败和中途崩溃造成的绑定丢失。 |
| AG-A06 | Session FIFO 和 setup 缓冲均有界；控制故障独立通道；ACP 帧、外部 prompt 设大小限制。 | 单会话积压不能阻塞整条共享连接，畸形或过大输入明确失败。 |
| AG-A07 | 依据实质活动管理超时，工具运行和权限等待暂停计时；停滞重试必须先得到取消响应，次数有界。 | 兼顾长工具任务与真正卡死；已有输出保留，因此不承诺执行或回答恰好一次。 |
| AG-A08 | 连接重启指数退避并熔断；弱引用避免 actor 自持，停止旧进程后才启动替代代次。 | 抑制故障重启风暴与循环引用造成的资源泄漏。 |
| AG-A09 | 包内 CLI 由 Host 解析，仅明确缺失时回退 PATH；损坏、越界和非法文件直接报错。 | 避免把坏安装伪装成“找不到 CLI”并误运行另一程序。 |
| AG-A10 | 模型按真实 cwd 按需发现，有独立超时；模型偏好经握手确认，思考强度来自 provider 实时配置。 | 不复用其他工作区的错误结果，不向用户展示编造的模型能力。 |
| AG-A11 | 权限响应核对 pending 请求和所属 option，重复或非法选择拒绝；当前自动选 AllowAlways/AllowOnce，没有允许项则取消。 | 保证响应关联正确；这是自动允许策略，不是已实现用户逐项审批。 |

## 6. 对话历史、降级恢复与 Agent 切换

| 编号 | 已落地措施 | 解决的问题与适用边界 |
| --- | --- | --- |
| AG-H01 | Host 保存 append-only JSONL 历史，按 UUID 分片；用户输入先记录再发送，更新先记录再转发。 | 历史不依赖某个 provider，前端断线或插件卸载后仍可查看。 |
| AG-H02 | 流式片段汇聚，逻辑 position 排序，同位置后写记录修正旧项；工具、计划和媒体保留位置。 | 在减少碎片记录的同时保留交错输出及工具后续更新。 |
| AG-H03 | TurnEnded 明确完成或取消；工具计时使用真实开始锚点和单调持续时间，终态冻结。 | 不把未完成工具当作成功，也不根据缺失数据补造耗时。 |
| AG-H04 | 崩溃尾部与损坏完整行分开处理；写失败进入 Degraded，拒绝继续 prompt，显式恢复先补 Gap。 | 将历史缺口暴露给用户，避免在不可靠记录上继续追加。 |
| AG-H05 | 历史读取兼容旧 schema 与新增可选 timing 字段；Session 各类修改只更新其拥有的列。 | 旧记录可继续使用，过期 actor 快照不会覆盖标题等无关变更。 |
| AG-H06 | 切换保留业务 Session 和历史；新 Agent 握手、配置成功后再替换旧绑定。 | 降低失败切换破坏原会话的风险。 |
| AG-H07 | 由 AgentSwitched/HandoffDelivered 记录推导待交付历史，下一条 prompt 接受后才结清。 | 交接可跨重启恢复，不将“已记录输入”误当成“已交付上下文”。 |
| AG-H08 | transcript 保留用户/助手文本，工具压缩为标题和状态，媒体占位；标记来源并转义边界标记。 | 给新 Agent 明确的历史材料，但不伪造其原生会话或承诺无损交接。 |
| AG-H09 | 停止优先 close 保留 provider 历史；删除仅清理 Ora 自有历史与记录。 | 区分会话停止、业务删除与第三方数据所有权。 |

## 7. MCP 选择、会话刷新与健康探测

| 编号 | 已落地措施 | 解决的问题与适用边界 |
| --- | --- | --- |
| MCP-01 | Session 持久化 Automatic 或 Explicit 选择；新建普通聊天自动发现，工作流冻结节点白名单，旧会话按迁移记录保留选择。 | 安装不等于工作流授权，恢复不依赖易丢失的 NodeRun 关联反推权限。 |
| MCP-02 | 先按选择过滤再读取配置，按 canonical ID 排序；Automatic 只纳入合格完整成员，Explicit 缺失或配置不完整则整组失败。 | 无关插件的配置或凭据不进入会话，显式集合不会静默降为部分工具集合。 |
| MCP-03 | 创建、恢复、切换、重建与在线刷新共用 Session Setup；检查 transport 和 provider 能力。 | 避免某条会话路径漏掉 MCP，不能用历史注入冒充动态加载能力。 |
| MCP-04 | 持久选择与实时包版本/配置 revision 分离；Desired/Active 版本及 barrier 协调变更。 | 忙时延后刷新，刷新失败阻止用旧配置开始新 prompt。 |

| MC-03 | 前端发送前保存未确认身份和输入，丢响应或刷新后重试原请求。 | 避免用户重试创建第二次 clone；session storage 不充当历史数据库。 |
| MC-04 | 400/409/503、不存在和未完成分开；关闭页面/server 不取消已接受 Node 执行。 | 暂时无法查询不等于业务失败，恢复后继续原结果。 |
| MC-05 | 启动器按 checkout digest 隔离目录，记录归属，独占锁；重复启动保留配置、数据库和 checkout。 | 多个 checkout 不覆盖彼此数据，恢复失败不清库重建。 |
| MC-06 | 组件异常或 Ctrl+C 按序停止前端/server、Node、Host 与专用 Guardian，超时报错并升级信号。 | 退出过程有明确资源责任，但不承诺终止所有逃逸后代。 |
| MC-07 | 只允许回环监听，测试覆盖真实 HTTP/Vite proxy、响应截断、SIGKILL、重启和唯一变更 Run。 | 当前为非生产本机应用；不等于认证、多租户或完整浏览器验收。 |

| OPS-08 | 诊断导出经 Host 原生保存动作，前端不获取任意私有日志路径；插件级别可持久化实时更新。 | 让用户获取排障材料，同时保持文件访问能力集中。 |
| OPS-09 | Scheduler 显式时区、注册前解析 cron，以句柄表达取消/detach；区分待执行、已运行和已完成。 | 防无效作业启动与含糊取消语义。 |
| OPS-10 | 同一 cron 不重叠，错过 tick 不补跑；supervisor 用 JoinSet 管全部任务，shutdown 拒绝新注册并等待清空。 | 控制进程内作业生命周期；不承担持久调度、分布式协调或通用失败重试。 |

## 完成度、边界与未计入的能力

下列区分是使用这份清单时的重要前提，不能把局部机制扩大为产品级保证。

| 主题 | 当前能确认的事实 | 不应宣称的能力 |
| --- | --- | --- |
| 工作流节点 | Start、Agent、Condition、Output、Loop、Iteration 有执行实现。 | Prompt/Tool 等可识别类型不等于可执行；没有通用任意节点自动重试或暂停恢复保证。 |
| 循环 | Loop 已有调度与恢复测试；foreach 逐轮串行，区域内可含并行分支。 | 任意循环嵌套、失败后从容器中任意一轮/子节点继续。 |
| 工作流导入 | 按文档解析并顺序创建/发布，分别报告结果。 | 整份导入跨步骤原子性，或解析通过就已验证所有运行前提。 |
| Agent 交接 | 记录交付债务，下一 prompt 注入现有 transcript。 | token 预算编译、语义压缩、历史检索工具、HandoffPacket 或无损接管；当前长历史可能超模型窗口。 |
| 历史耐久 | append/flush、显式损坏与 Gap 处理。 | 每条消息 fsync、断电零丢失，或多个 Ora 进程共享 history 根并发写入。 |
| Agent 插件权限 | Host 接口受身份约束，Workbench 最小授权。 | Agent 强沙箱：当前 Agent 仍有 Deno run/read/env/net 能力，能运行子进程。 |

## 文档维护方式

- 新增措施时记录“在哪个功能中解决什么问题”，同时补充当前实现与测试入口，不只写技术名词。
- 涉及恢复、隔离、原子性、耐久性、权限时，写清证明范围与仍存在的失败窗口。
- 源码与阶段性文档冲突时，以当前实现为准。例如部分执行作用域文档仍描述 Loop 未开放，部分 Node 文档仍描述 clone 未接通；本清单已结合当前调度器和独立进程闭环代码判断。
- 本清单随代码演进更新，中英文版本及措施编号保持对应；不将这份快照当作永久验收报告。
