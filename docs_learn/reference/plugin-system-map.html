Ora 插件系统速查图

从可下载的发布清单，到可信的安装贡献，再到可选的进程数据面。记忆主轴：先验证“是什么”，再决定“谁消费”，只有少数贡献需要进程。

Registry找到发布版本、URL、SHA-256 与目标平台。
Manifest把 TOML 解析成满足语义约束的领域对象。
Manager检查磁盘内容，产出唯一的 Contribution 枚举。
ConsumerLifecycle、Agent、Surface、Skill Catalog 等按类型消费。
Kind包的核心贡献Deno 进程主要消费者
agentmain.js Agent adapter；可携带 CLI binary按需Agent Runtime
workbench包内页面 + main.js bridge backend首次 bridge 调用时Surface Host
webview远程 HTTPS URL、origin 与下载策略无Surface Host
skill一个或多个静态 Skill package无Skill Catalog / Effect
mcp静态 transport + settings configuration无安装与配置层；运行时后续实现
hookHook 协议描述 + 原生 executable无未来 Hook consumer
面试高频陷阱：“没有 Deno 插件进程”不等于“没有可执行文件”。Hook 自身就是原生 artifact；MCP stdio 也声明包内 command；区别在于它们不是由通用 Plugin Runtime 启动的长期 JavaScript 插件进程。

层与所有权

层只负责刻意不负责
plugin-manifest纯文本 schema 与语义磁盘、网络、进程
plugin-manager安装、发现、磁盘验证启动、停止、协议通信
plugin-runtime一个 Deno 进程与双向协议插件类型的业务含义
plugin-lifecycle进程唯一所有权、状态、generationAgent/Surface 上层语义
backend consumers把 Contribution 适配成 Agent、Skill、Surface 等产品能力绕过底座自行启动插件
