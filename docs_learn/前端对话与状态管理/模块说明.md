# 前端对话与状态管理

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

理解界面草稿、聊天流、查询缓存与真实后端记录之间的关系，避免把“显示了”当成“存好了”。

## 设计逻辑与执行流程

`packages/app-shell` 组织功能，`packages/chat` 管对话事件到消息视图的状态，`packages/editor` 管输入编辑。平台接口通过 Tauri 适配器调用后端。

数据分三类：后端权威数据由查询缓存展示；草稿和 UI 偏好由前端 store 管理；正在生成的内容由流式状态更新。持久化成功后优先采用后端返回对象，再做 UI 选择／草稿清理。

应用事件的订阅与重连和缓存失效规则分开：title event 提醒重取 Session；连接恢复后主动 refetch Session 补漏。不同插件事件对模型／运行时／技能的失效范围不同，不能一律全量刷新。

选择 Agent／模型可以先暂存，真实 Session 在发送时创建或换绑。打开多个视图不应复制 prompt owner；跟随者慢到超过上限会得到显式流错误。

工作流编辑器图形状态与后端 draft 分开；`workflow-mock` 的内存运行也与真实持久化运行缓存分开。画布能演示一条链路，不代表真实 backend 支持该节点。

## 数据库表与持久化

| 数据 | 存储 | 持久化边界 |
| --- | --- | --- |
| Session／任务／工作流列表与详情缓存 | 前端内存 | refetch 从相应数据库恢复；缓存不是数据库 |
| 聊天正文展示状态 | chat store 内存 | 后端 JSONL 回放恢复 |
| 未发送聊天草稿 | draft-sessions store 的 localStorage | 无 `sessions` 行，也未创建 provider Session |
| 默认 Agent／主题／模型偏好／部分 UI 状态 | 各自 localStorage store | 只在当前客户端恢复 |
| pending Agent switch／pending model | 内存 store | 提交成功才反映到后端绑定／provider 配置 |
| 已保存工作流编辑内容 | `workflow_snapshots.graph` | 通过后端 draft 保存请求持久化 |
| mock 工作流运行 | memory runtime | 不写 `workflow_runs`／`workflow_node_runs` |

涉及业务保存时仍通过后端 `sessions`、`tasks`、`workflows` 等 repository；UI 不直接写 SQLite。

## 目前存在的缺陷与限制

- **已确认的限制**：localStorage 不提供跨客户端同步；清理 WebView 存储会丢失未发送草稿／偏好，但不应影响已落后端的正文。
- **已确认的边界**：原型设置和 mock 运行不能视为真实执行能力或安全策略。
- **设计风险**：事件与缓存存在延迟、断连和旧响应覆盖风险；要采用权威响应、分域失效和重连 refetch，不能只改界面对象。
- **验证约束**：React 测试中未 await 更新、未初始化 appI18n 会产生 stderr 并令 CI 失败；“Vitest 绿了”不足以证明验证通过。
