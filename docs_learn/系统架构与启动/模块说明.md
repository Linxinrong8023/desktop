## 模块职责

理解一次界面操作如何穿过前端、桌面适配器、业务层和存储层，以及启动时由谁组装这些对象。

## 设计逻辑与执行流程

主链路：`React → 平台接口／Tauri command → Backend 模块 API → application handler → repository Trait → ora-db`。领域值对象在 `ora-domain`，对外 DTO 和错误合同在 `ora-contracts`。流式对话通过 channel 回传，不是普通请求返回一个超长字符串。

- `apps/desktop/src-tauri` 管窗口、IPC、平台能力和服务生命周期；`ora-backend` 组装数据库、插件、Agent、工作流、恢复扫描等能力。
- `ora-application` 表达业务操作，依赖存储／时钟／标识生成等接口；`ora-db` 实现 SQLite 细节。单测可以替换这些依赖。
- `ora-fs` 管工作区文件，`ora-gitlancer` 管 Git，`ora-process`／`ora-pty` 管进程能力；通用路径与归档工具在 `ora-utils`。
- 启动先确定路径和数据库结构，再完成必要的资料恢复、状态校正与运行时组装。创建窗口与初始化后端不能混为一件事。
- 请求错误由外层映射成稳定的公开错误；日志可以保留来源链。前端不应依赖 SQLite 错误字符串进行分支判断。

阅读时先找公开 API 的入口，再沿调用追到 repository；看见类型定义不代表该能力已经被 UI 或运行时接入。

## 数据库表与持久化

本模块不拥有一张“架构表”，但负责打开其他模块共用的存储：

| 位置 | 内容 | 创建／恢复方 |
| --- | --- | --- |
| `<app_data_directory>/ora.sqlite3` | 49 张当前表，包括 `migrations` | DatabaseBootstrapper 与各 repository |
| `<app_data_directory>/sessions` | 会话 JSONL；`node-baselines` 为工作流交互基线 | history 与 workflow 模块 |
| `<app_data_directory>/atoms/skills` | 本地技能包及事务恢复资料 | Skill 模块 |
| `<home_directory>/worktrees` | 默认任务工作树根目录 | 任务模块；用户可配置其他位置 |

这些是 Backend 接收路径后构造的位置，不要把某台机器的绝对目录当作代码常量。SQLite 迁移只解决数据库结构；文件恢复由各自模块负责。

## 目前存在的缺陷与限制

- **已确认的边界**：启动校正会话状态不等于恢复上次正在执行的 prompt；工作流孤儿执行也有独立失败处理。
- **设计风险**：SQLite、Git、JSONL、插件配置文件没有共同的全局事务。跨模块操作要逐一检查补偿和恢复，不能根据某个 handler 返回成功就推断所有外部副作用永远一致。
- **学习材料风险**：历史课程里关于旧服务入口、Warm Session 或旧 Effect 方案的描述可能已经过时。本目录以当前入口及源码为准。
