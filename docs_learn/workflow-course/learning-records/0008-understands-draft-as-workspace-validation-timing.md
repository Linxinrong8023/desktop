# Understands Draft-as-workspace validation timing

The learner correctly explained that users build workflows incrementally, so requiring every Draft save to be fully executable would transfer implementation-state burden to the user and damage the editing experience. Draft persistence is now understood as saving work in progress rather than certifying deployability.

## Evidence

When asked why incomplete Drafts may be saved, the learner immediately reasoned that workflows are not created in one step and that strict save-time validation would impose an inappropriate user burden.

## Implications

The course can now discuss validation gates, autosave, publish-versus-run admission, and the trade-off between flexible authoring and earlier feedback.
