# Agent 故障分类、重试与熔断

## Learner response

用户正确判断：Agent CLI 未安装时应静默退避并持续重试；插件漏注册 `agent/acp` 时应直接失败且不重试。面对 ACP `initialize` 偶发超时，用户判断需要逐渐增加间隔重试，并知道存在故障次数限制。

## Mastered

- 能区分预期环境缺失与确定性合同错误。
- 知道 CLI 未安装发布 `Unavailable`，持续退避且不计入 crash circuit，环境补齐后可自动恢复。
- 知道合同缺失发布 `Failing`，同一错误包原样重启无法恢复，因此不进行无意义重试。
- 能将偶发握手超时归入可重试的真正故障，而不是误判为永久不兼容。

## Precision corrections

1. 真正故障不是按 Backend 生命周期设置固定的“总重试次数”，而是使用一分钟滑动窗口；一分钟内第四次真正故障才打开 restart circuit。
2. 合同错误不一定通过“重新安装”恢复。重新安装相同错误版本没有意义，需要修复或更新插件，并重新建立运行环境。
3. 普通启动或连接故障重试前会回收旧 generation，等待其进程树退出后才创建替代 generation。

## Mastery status

第 18 课的三类故障决策已掌握：预期缺失静默持续重试，异常可恢复计入滑动窗口并退避，确定性不兼容立即 Failing。后续通过跨课程场景复习熔断窗口精度。
