# 工作流执行与恢复

> 核对日期：2026-09-10；依据本地 `project_learn` 分支源码。本文是当前实现学习说明。

[返回学习导航](../README.md)

## 模块职责

学习 DAG 调度、节点执行记录、交互等待、取消与重启后的持久化恢复。

## 设计逻辑与执行流程

start 根据选定 Snapshot 构造不可变图，检查节点唯一、边有效、无环、至多一个 start，以及节点实际支持情况。拓扑顺序稳定，变量和上游结果可以按固定顺序组装。

引擎按已持久化节点状态重新计算可执行集合；节点执行记录代表一次尝试，不是图定义。记录按需要创建，不意味着启动时给所有节点预填一行。分支决策影响后续可达节点和输出投影。

Agent 节点先准备 Skill 交付和运行目录，再调用真实 Session prompt。Session 创建后暂时 unpublished，只有 prompt 获准且节点仍未终止时才提交 `workflow_node_runs.session_id`，防止取消获胜后又挂上活会话。

交互节点可以在 Pending 状态等待后续输入／人工完成。继续输入、完成、取消共用 run gate，持久化终态优先于 best-effort Session 收尾。节点 output 是最终 assistant 文本，完整聊天留给 Session。

启动恢复将上一进程遗留的非终态节点标记 Failed／`interrupted_by_restart`，再协调仍可调度的 Running Run；不会假装上次外部工具能无缝接着执行。孤儿 baseline 文件在启动扫描回收。

## 数据库表与持久化

| 表／文件 | 内容 | 写入时机 |
| --- | --- | --- |
| `workflows`、`workflow_snapshots` | 定义及冻结 graph | 启动读取，运行不能改旧快照 |
| `workflow_runs` | `workspace_id,workflow_id,snapshot_id,run_status,state,input,output,error,payload` 及起止时间 | 创建、调度状态推进、完成／取消／恢复 |
| `workflow_node_runs` | `run_id,node_id,node_type,session_id,status,input,output,error,payload` 及起止时间 | 创建一次尝试、绑定会话、结果／等待／终态 |
| `sessions` 与 JSONL | Agent 节点完整对话 | Session runtime 按真实对话写入 |
| `<sessions_root>/node-baselines/<node_run_id>.json` | 交互节点文件变化对比基线 | 等待交互期间保留，终结／启动扫描清理 |
| `effect_*` | Skill 选择与实际交付、readiness | prerequisites／交付协调 |

`workflow_node_runs.session_id` 是可空 TEXT，**没有 SQL 外键**；属于应用层绑定协议。未绑定不一定是错误，也可能正在准备 prompt。不要往 node output 重复存整个 transcript。

## 目前存在的缺陷与限制

- **已确认的功能缺口**：Start／Agent／Condition／Output 可执行；Prompt／Tool 虽然在枚举中被识别，当前不支持执行，start 会拒绝。
- **已确认的恢复限制**：boot sweep 是 best effort，存储故障记录日志但不阻止全部启动；Interrupted 节点不是自动成功，也不是外部动作 exactly-once。
- **已确认的关系约束缺口**：session_id 无物理外键，必须靠 terminal 状态校验与绑定操作维护一致性。
- **设计风险**：人工等待基线是独立文件，表提交与删除文件之间可留下孤儿；启动清理只能按当前数据库事实处理。
