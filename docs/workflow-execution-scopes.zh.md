# 工作流执行作用域存储

[English](workflow-execution-scopes.md) | 中文

迁移 `0013` 为 [Loop 实现](workflow-loop-plan.zh.md)增加执行身份，但不开放 Loop 调度。

`workflow_execution_scopes` 存储根作用域与各轮次。根作用域没有父节点、轮次序号、状态或状态数据，其当前执行状态仍由现有 Run payload 持有。轮次作用域包含父 Loop NodeRun、从 1 到 100 的轮次序号、生命周期状态及 JSON 状态。`workflow_run_root_scopes` 指向每个运行的当前根作用域。重跑后保留历史根作用域。

旧节点会回填 `workflow_node_runs.scope_id`。未指定作用域的插入会在同一 SQL 语句内归入当前根；显式指定作用域时，必须属于同一运行和当前执行。节点的作用域身份一经赋值不可更改。部分唯一索引禁止同一作用域内重复创建活跃的定义节点，不同轮次可以执行相同定义。每个 Loop 只能持有一个待执行或运行中的轮次，同一父 NodeRun 下的轮次序号唯一。

重跑在重置运行、软删除旧节点实例的同一事务内创建新根作用域。旧节点保留原作用域 ID。轮次的父节点必须是当前根作用域内正在运行的 Loop，防止嵌套循环和通过旧根创建新轮次。

降级使用生产启动协调器保存的 `down_sql`。删除作用域表及节点作用域列前，先向 `workflow_scope_downgrade_archive` 追加完整的作用域与节点快照，终止持有 Loop 实例的活跃运行，并软删除子节点实例，避免旧读取路径将其当成普通节点。扁平运行、Session、Workspace 和用户文件保持不变。归档有意保留到降级和再次升级之后，作为历史证据，不作为可恢复的执行状态。归档的界面交付仍属于待完成的历史展示工作。

测试覆盖升级回填、默认根归属、唯一性及所有权约束、生产仓储重跑、旧版本实际启动路径和重复降级再升级。开放 Loop 执行前，仍需实现原子反馈推进和运行时作用域投影。
