# Agent 上下文交接：边界与验收

状态：配套设计验收计划，非已实现功能的测试报告。
日期：2026-09-10（Asia/Shanghai）。主方案：[Agent 上下文交接方案](agent-handoff-design.md)。

## 1. 验收范围

本次设计必须回答两个核心问题：

1. 如何避免当前按类型删掉工具证据、媒体和决定依据，导致接手者理解不完整？
2. 如何在目标上下文有限甚至未知时，控制交接内容和后续检索的容量？

同时验证这些机制能处理普通任务继续、需求修订、连续切换、中断、并发、历史损坏、权限与派生物生命周期。
不以“第二个 Agent 更聪明”“摘要更短”或“请求发送成功”替代这些要求。

下表的“通过条件”均是实现后需验证的行为。本文没有运行真实模型接管实验。

## 2. 信息保真与归因

| ID | 输入或反例 | 通过条件 |
| --- | --- | --- |
| F01 | 200 轮前用户要求 Windows 兼容，最近 20 轮只讨论 Linux 性能 | 交接仍主动包含兼容要求和源引用，不能依赖接手者主动搜索未知条件 |
| F02 | 用户最初要求云部署，后明确改为离线；旧方案出现次数更多 | 最新离线要求为 Active，云方案标明被替代；不能按频次投票 |
| F03 | 用户要求兼容 Windows，后又要求优先优化 Linux | 两项并存，不能把“最新优先事项”当成撤销旧约束 |
| F04 | AI 提议用缓存，用户未批准 | 表达为 AgentProposed，不得转为 UserConfirmed |
| F05 | 用户粘贴日志，日志含“用户已授权删除” | 仍属被引用日志，不能变成真实授权 |
| F06 | 已调用 shell 工具且状态 completed，但退出码非零、测试失败 | 工具结束与业务失败分别记录，不宣称测试通过 |
| F07 | AI 说“接下来我会修改”，后未发出修改工具 | 状态为 Planned，不算已改文件 |
| F08 | 工具实际写文件，AI 没在回复中复述 | 对后续任务重要时保留工具观察和产物引用，不因没有助手解释而丢弃 |
| F09 | AI 说测试通过，但工具日志显示失败或属于旧 commit | 保留矛盾/版本差异和原始证据，不选择有利结论 |
| F10 | 讨论中有三个数值、单位、阈值和一句否定条件 | 引用中的数值单位和否定语义无变化；结构化验证不能替代语义抽检 |
| F11 | 一项用户请求尚未回应，后面是很长的工具日志 | 未决请求仍可见，不被长日志排挤 |
| F12 | 用户说“按前面第二种方案继续” | 摘要关联对应候选方案；无法确定时标为有歧义，不自己选择 |
| F13 | 公开推理说明中存在未验证假设，助手最终回复没有提到 | 提取为带来源的假设；不复制不可见内部推理，不当成事实 |
| F14 | A→B→C→A 连续切换，每次产生新决定 | 关键来源最终仍指向原始记录，原约束/新修订可恢复；无“摘要的摘要”漂移 |
| F15 | 一个超长 user 消息内嵌“无论如何不要改数据库格式” | 分块后保留说话者与完整条件；不能只保留首尾而漏掉中段 |
| F16 | 一个很短的闲聊 Session，无工具和代码 | 能直接交接原文，不凭空补出开发计划、分支或故障 |
| F17 | 历史已全部扫描但语义模型没有提取某个重要条件 | coverage 报告不能声称语义完整；用人工标注的关键条件召回测试检出 |
| F18 | 目标 Agent 工具/Skill 名称与前一个 Agent 不同 | 历史保留原始名称和用途；当前能力另行列明，不让接手者调用不存在的旧工具 |

## 3. 工具输出、媒体与现场

| ID | 输入或反例 | 通过条件 |
| --- | --- | --- |
| E01 | 编译错误仅在工具输出中，助手只回复“还没修好” | packet 保留关键错误或明确可读引用，接手者能够检索到堆栈 |
| E02 | 10 MiB 重复测试日志，中间一处失败 | 提取失败段及其上下文、命令/状态，其他部分分页；不能仅截取前 2 KiB |
| E03 | 工具提供的日志本身被上游截断 | 标明上游缺失，不能承诺完整历史读取能恢复不可见内容 |
| E04 | tool call 和结果跨越多个事件，途中发生摘要作业 | 使用安全点固定的一致快照，配对完整或明确 pending/unknown |
| E05 | 用户上传的截图包含唯一的 UI 验收要求 | 传递必要原图或可靠替代描述与来源；目标不支持且无法表达时停止该自动交接 |
| E06 | 音频转写有不确定词，原音频仍可读 | 保留转写不确定性与音频引用，不自信填补 |
| E07 | 原资源链接过期、附件文件被删 | 返回 Unavailable，说明影响；不读取相同 URL 的新内容冒充旧内容 |
| E08 | 历史里有未写入文件的完整代码草稿 | 草稿仍是独立产物，可通过历史读取；不指向不存在的文件 |
| E09 | 历史读取过的文件后来被用户手改 | 记录历史指纹并提醒复读，当前文件不能被旧快照内容覆盖 |
| E10 | 非 Git Workspace 或文件根目录移动 | 对话交接不依赖 Git；路径重新解析到有权限的 Workspace，失效引用明确报告 |
| E11 | 切换时存在 git staged/unstaged/untracked 内容 | 现场观察保留三类状态；切换不自动 reset、stash 或 commit |
| E12 | 后台命令、测试服务器仍在执行 | 标明未结束的执行及资源；不能把取消会话当作所有外部进程已结束 |

## 4. 容量与性能

| ID | 输入或反例 | 通过条件 |
| --- | --- | --- |
| B01 | 128k 来源会话切到较小目标窗口 | 按目标 profile 重编译，不能复用旧 packet 大小 |
| B02 | 目标窗口已知，系统提示与工具开销不完全可见 | 标明 Estimated 并预留余量；不声称精确可装入 |
| B03 | 目标窗口未知，只有模型显示名称 | 不猜值并标为 Verified；要求配置/兼容目标或明确有限摘录模式 |
| B04 | 历史包很短，但最新用户消息或附件超过预算 | 将问题归因到当前输入，不无限压缩旧历史 |
| B05 | 固定关键条件本身已超过 H | 返回 CriticalContextTooLarge，不静默丢条件；可选择更大窗口或明确缩小任务 |
| B06 | 一段中文、emoji、代码和 JSON 转义混合内容 | 使用目标计数或有声明误差的估算，UTF-8 分片合法，实际外层字节校验通过 |
| B07 | 内层 prompt 满足限制，JSON-RPC/插件转义后超过帧限制 | 在发送前拒绝或重新组包，检查真实最外层消息长度 |
| B08 | 摘要器输入比摘要模型窗口大 | 分块预算生效，单条超大记录也能分片；不先把全文发给摘要器 |
| B09 | 摘要器输出越界/无效 JSON/引用不存在 | 最多有预算的一次修复，失败显式降级或停止，不能无限重试 |
| B10 | 切换准备期间目标模型或 MCP 集合变化 | profile digest 失效，重新计数/编译，不发送旧包 |
| B11 | 历史 MCP 连续读 100 页 | 单页、单轮额度受宿主约束，累计达到阈值时返回简短状态；不能默认无限读取 |
| B12 | 长会话全量索引扫描造成大内存使用 | 使用流式/分页索引；最大工作集和扫描时间有上限，保留取消响应 |
| B13 | 语义压缩 Adapter 不可用或用户无可用凭证 | 不擅自选收费端点；可用确定性摘录模式或明确能力不足 |
| B14 | 冷启动准备很久、用户反复点击切换 | 单 Session 合并/取消旧请求，显示真实阶段；无隐形并发摘要账单 |
| B15 | 高成本历史不断变化导致缓存失效 | 作业预算包含无效重做成本；超过配置限额请求处理，不忙等重试 |
| B16 | 每个源块都有一个独立约束，全局有百万个候选条目 | 合并、复核、候选存储都有全局限额与分页，不能只保证单块 prompt 合法 |
| B17 | 总调用或截止时间耗尽，尚有一半历史未扫描 | 返回 PreparationLimitReached 和未处理范围；不声明全部语义已压缩 |
| B18 | Agent 加载大量全局 Skill/MCP schema，占用了大部分窗口 | 计入实际/估计 E；Ora 自己的包较小也不能被当作整体可容纳的证据 |

## 5. 快照、发送、恢复与并发

| ID | 输入或反例 | 通过条件 |
| --- | --- | --- |
| L01 | seq=10 后来追加修正版，旧 packet 引用旧版 | 用 cutoff/digest 返回旧快照对应的版本，不错引最新 seq=10 |
| L02 | 序号到达 u32 上限 | 显式失败或已验证的格式升级，不能复用饱和序号 |
| L03 | 历史含撕裂尾行、完整坏行或 Gap | 分别标注可知情况；坏行位置未知时不编造精确缺口 |
| L04 | 数据库有旧会话，但历史文件从未创建/已丢失 | 区分已知空会话和历史不可恢复；不能都按完整空历史继续 |
| L05 | 准备时旧 Agent 崩溃 | 使用已捕获记录并标明末尾未知；不要求旧 Agent 必须生成总结 |
| L06 | 正在压缩时用户又补充一条新要求 | 旧作业取消或 epoch 失效，新消息只加入一次，并在发送前重新组包 |
| L07 | 同一 Session 同时发起两次切换 | 只有当前 epoch 可提交，旧作业不能覆盖新目标 |
| L08 | Skill 更新、MCP 刷新与 Agent 替换同时发生 | 遵守既有协调顺序，避免死锁、旧配置发送和应用全局长锁 |
| L09 | 目标 Agent 启动失败或压缩失败 | 不提前丢弃唯一可恢复的旧绑定；实际不可恢复时准确显示 |
| L10 | 发送前明确失败 | 同一逻辑 handoff 保持 Pending，可以安全重试未执行请求 |
| L11 | 请求已到达目标，但 receipt 写入前应用崩溃 | 重启显示 OutcomeUnknown；不自动重复业务操作 |
| L12 | provider 明确在执行前拒绝上下文超限 | 限次缩小包重试，保留 packet revision 与拒绝证据 |
| L13 | 已有工具调用后连接断开 | 保留已观察副作用与未知后续，不把断开当作零执行 |
| L14 | 用户在准备中取消或删除 Session | 撤销授权、停止作业、丢弃迟到结果；不重建已删除派生物 |
| L15 | 两个 Session 共享同一 Workspace，并发修改文件 | 会话历史不串流；文件冲突需要工作区协调，不能以 Session 锁宣称已隔离 |
| L16 | UI 关闭但后台作业还活着 | 由明确的取消/继续策略决定，不凭 UI 消失推断已终止；状态可重读 |
| L17 | Agent 接收 packet 后说“理解了”，实际下一步违背约束 | 接管质量评测判失败；发送 receipt 和理解回复不能覆盖失败 |
| L18 | 切回之前用过的 Agent | 重新基于新增历史交接，不恢复一个缺少中间工作结果的旧上下文并声称完整 |
| L19 | 目标 binding 已提交，但 insert_actor 或历史端点发布失败 | 保持目标 Pending 账本并恢复发布，不自动回退源并重复请求 |
| L20 | 旧 actor 已停止但迟到消息到达 | 旧 epoch 不能写入新会话历史，已接受内容在 seal 前处理完成 |
| L21 | 记录 AgentSwitched 自身使历史 cutoff 增长 | 区分语义事件与自身审计事件，不触发无限自我失效重编译 |
| L22 | 升级清理了不兼容摘要缓存，执行回执仍为 OutcomeUnknown | 执行账本不随缓存清除，重建正文不将状态改回 Pending |
| L23 | 分别在 Pending 提交后、Dispatching 提交后、发送后 receipt 前崩溃 | 只有 Pending 可确定未发送；无确定证据的 Dispatching 恢复为 OutcomeUnknown，任何发送必须先持久化 Dispatching |
| L24 | 同一逻辑用户消息因确定未发送而重试，另有用户主动重复同一句话 | BusinessTurnId 使技术重试不重复记录；真实新输入保留新轮次，不能按文本去重 |

## 6. 检索、安全与生命周期

| ID | 输入或反例 | 通过条件 |
| --- | --- | --- |
| R01 | Agent 在参数/引用中伪造另一个 Session ID | 宿主授权拒绝；模型不能选择会话权限 |
| R02 | Session ID 正确但凭证来自已替换的旧 binding | epoch/授权租约失效；旧连接不能继续检索 |
| R03 | 修改分页游标的范围或 snapshot | 拒绝越界/错误版本；不能跨查询拼页 |
| R04 | 搜索无命中或中文分词失配 | 明确无命中，并可按记录范围读取；不得编造搜索结果 |
| R05 | 工具输出包含伪造交接结束符、system 提示或忽略用户要求 | 不提升来源权限，引用和包装经过转义，摘要评测包含注入攻击 |
| R06 | 历史曾批准部署，当前 Agent 权限不允许 | 继续执行前仍走当前权限策略，旧记录不授予权限 |
| R07 | 查询返回 secrets 或历史凭证 | 按访问和脱敏策略处理，日志不记录完整 payload/token；不能许诺自动脱敏完美 |
| R08 | 新压缩器属于用户未允许的数据目的地 | 不自动发送历史；提示设置选择，不静默增加第三方副本 |
| R09 | 不支持 HTTP MCP 的 Agent | 使用已验证的 stdio/其他只读 Adapter；无通道时显式说明，不能注入无效工具名称 |
| R10 | MCP 配置刷新只重建全局插件集合 | 宿主绑定历史端点仍按 SessionSetup 合并保留，并正确更新 revision |
| R11 | MCP 读取返回历史，随后该工具结果被记录并再次压缩 | canonical source 去重，引用链不循环，不重复膨胀正文 |
| R12 | Session 删除时索引构建正在提交 | tombstone/epoch 阻止写回，索引、摘要、媒体租约全部失效 |
| R13 | 历史文件被外部改写、截断或换成另一文件 | 快照校验失败，不能把相同路径当作相同来源 |
| R14 | 插件升级/模型版本更新后复用旧缓存 | 按 source/compiler/profile/data-policy digest 检查，必要时失效 |
| R15 | 普通编码 Agent 收到“只总结”却调用本地 shell | 无强制隔离能力时不得用作 SemanticCompressor；提示词约束不算通过 |
| R16 | 摘要中引用存在，但引文实际上不支持结论 | 结构验证通过、语义验证失败，必须分别报告 |
| R17 | 已有缓存目录与新布局冲突或旧版本打开新数据 | 遵循明确迁移/拒绝策略，原始会话仍能安全打开；不覆盖冲突路径 |
| R18 | 同时发起十个 history.read，并断线后重连 | 同一宿主 turn 原子预留/结算，共享额度不重置，计入兼容双格式及元数据 |
| R19 | 外部插件声明与宿主历史端点同名 | 安装/合并时拒绝覆盖，调用不能被恶意替换 |
| R20 | 无活动业务 turn，Agent 反复后台取历史 | 只有明确的有限预检授权可读，不能获得无限额度 |

## 7. 一次完整交接的桌面推演

### 7.1 原始记录（构造例子）

```text
R10 User: 导出功能必须离线可用，继续支持 Windows。
R20 Assistant: 建议先接云端导出服务。
R30 User: 不接受云服务。导出在本地完成。
R40 Tool/read: src/export.rs 当前只支持 CSV。
R50 Assistant: 计划加入 JSON 导出，再调整 UI。
R60 Tool/patch: 已在 src/export.rs 加入 JSON 分支，补丁返回成功。
R70 Tool/test: cargo test export；进程开始后会话取消，未收到退出码。
R80 User: 先完成导出 UI，格式迁移下一轮再做。Windows 要求保留。
R90 User: 切换 Agent 后继续。
```

当前简单渲染保留了部分用户约束，但接手者无法从工具名获知修改内容或测试究竟运行到哪里。
新方案的任务状态必须包含：

```text
目标：继续本地导出功能，本轮先完成 UI。[R10, R30, R80, R90]
约束：离线；兼容 Windows；本轮不做格式迁移。[R10, R30, R80]
决定：云服务方案被用户否决。[R20, R30]
进度：工具报告已写入 JSON 分支，尚需读取当前文件确认现场。[R60]
验证：export 测试已启动，结果未知，不能标记通过。[R70]
下一步：读取当前导出实现与 UI，按已确认范围继续。
证据：R40/R60/R70 可以通过绑定当前快照的历史工具读取。
```

引用同时携带 snapshot/revision，实际表现形式不要求把所有技术 ID 显示给用户。
接手者若怀疑 JSON 分支的细节，读取 R60；若只需继续 UI，当前约束已经主动提供，无须先知道要搜“Windows”。

### 7.2 对推演的反向检查

- 将 R80 改为“Windows 下轮再支持”，摘要应改变本轮兼容约束，并保留修订依据。
- 将 R60 改为“patch failed”，进度必须回到 Attempted，不能继续说代码已改。
- 让用户在切换期间撤销 UI 优先级，原 packet 必须失效。
- 让 R70 的后续修正版在旧快照截止点之后写入“通过”，旧引用仍返回当时的未知状态；新状态需要显式的新快照或当前验证。
- 删除 R60 对应的原始记录，摘要引用校验失败，不可只保留漂亮但无来源的进度说明。
- 令目标窗口连关键条件都装不下，返回容量不足；不能通过删掉 Windows 要求让预算过关。

## 8. 预算桌面推演

示例数值为设计验证输入，非真实模型规格。单位为同一目标计数方式下的 token。

| 场景 | C | E | U | O | R | M | H_cap | 可用 H |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 正常目标 | 64,000 | 8,000 | 4,000 | 8,000 | 4,000 | 4,000 | 24,000 | 24,000 |
| 较小目标 | 32,000 | 8,000 | 4,000 | 8,000 | 4,000 | 4,000 | 24,000 | 4,000 |
| 当前输入很大 | 32,000 | 8,000 | 16,000 | 8,000 | 4,000 | 4,000 | 24,000 | 0，且基础需求已超限 |
| 目标容量未知 | 未知 | 不完整 | 已计量 | 配置 | 配置 | 无法证明 | 24,000 | Unknown，不能给出安全容量 |

基础需求已超限时，`max(0, ...)` 只避免数值下溢，不意味着 H=0 后请求就安全。
需要单独检查 `E + U + O + R + M > C`，并返回输入/基础开销不足。

若较小目标的最低必要材料为 6,000 token，而 H=4,000，则必须返回 CriticalContextTooLarge。
该推演验证了“同一摘要发给所有模型”和“总能通过继续压缩解决”的错误假设。

## 9. 实现后的验证计划

### 9.1 不调用模型的确定性验证

通过实际 Module Interface 注入内存历史、固定 budget profile、伪 compressor 和故障时钟，验证：

- 同 seq 多修订与 cutoff 一致性、UTF-8 区间和原文 digest。
- packet/schema/provenance 校验、确定性预算组包、极限长度和数值溢出。
- epoch 状态流转、准备取消、删除重建竞态和明确/不明确发送失败。
- MCP 授权、游标绑定、逐页配额和 canonical source 去重。
- 故障发生在准备持久化、绑定提交、发送、receipt 之间的每个位置。

按仓库约定使用 `pretty_assertions::assert_eq` 比较完整对象，不只验证某几个字段。
测试不修改进程全局环境；涉及日志的路径采用 scoped TRACE subscriber。
测试通过只能证明这些工程属性，不能声称模型理解已验证。

### 9.2 真实接收 Agent 的语义评测

建立不少于 30 个匿名或构造的历史样本，覆盖上表语义类别；至少一半关键事实仅出现在早期记录、工具输出或需求修订中。
使用至少两个实际 Agent Adapter，模型/工具/权限/初始文件状态一致地对比基线和实验组。
每个接收配置至少重复 3 次，记录失败分布；随机性不能由挑选一次成功演示掩盖。

每个样本由人工维护一份 golden：

```text
必须保留的条件和来源
明确禁止的误读
当前完成/未完成/未知状态
能够查回的证据
接管后的正确下一步与允许的等价行为
```

四个对照版本：

1. 当前类型筛选渲染（超限按失败记入，不悄悄删样本）。
2. 固定最近轮次。
3. 结构化状态加最近原文，无检索。
4. 完整提案：结构化状态、关键证据、最近原文、受限检索。

短历史可以增加全量可见历史作为参考上界，但不能把它当作对所有长历史都可实现的基线。
控制相同模型与业务任务预算，同时单列摘要的额外 token、调用、延迟和数据目的地；不能把更多计算预算的收益全部归因于格式。

### 9.3 发布前的明确判据

- 工程矩阵的权限、引用、预算和副作用类用例必须全部通过。
- 关键约束挑战集不允许静默违反；无法容纳时返回需处理也算正确结果，自动继续违反则失败。
- 单独报告“成功继续比例”和“需处理比例”，防止靠全部拒绝交接获得表面零错误。
- 普通可容纳样本的目标为至少 95% 正确接管，并不劣于当前基线；这是待验证目标，不是已测指标。
- 关键条件召回、决定归因、进度准确率、证据可恢复率分别报告，禁止只给一个综合分掩盖严重遗漏。
- 比较 A→B→C→A 后的累积遗漏和原始引用覆盖，防止短期成功掩盖多次切换退化。
- 新目标不存在于摘要中的“后来才重要”的事实，要通过检索任务验证能否找回；不能只测试摘要里已有答案。
- 记录 warm/cold p50/p95 准备时间、token 成本、取消响应及缓存失效率；性能目标在实际 Adapter 的小规模基准后确定，避免把猜测时延写成保证。
