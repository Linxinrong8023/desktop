## 目标与设计依据

随后合入的上游 main `a54a4105` 在保留 Loop 容器与作用域历史的同时，保留 Iteration 悬浮插入、缩放、删除确认和区域级轮次导航。Loop 边界校验接入提取后的连接校验器，Loop 子节点仍能从执行路径中单独进入。已有的独立复合调度模块保留上游两项派发修复，无需恢复原先的大型实现文件。

在 Desktop 支持“生成 → 评审 → 修改 → 再评审”的有界反馈工作流。Loop 拥有可执行子图、有类型的跨轮变量、退出条件和最终输出。外层图与每一轮的子图均保持 DAG。

本计划采用此前讨论的 Dify 容器循环产品概念，独立定义 Ora 的语义；不承诺兼容 Dify DSL、依赖版本、持久化或当前 Human Input 能力。实施前，任何被作为兼容要求的上游行为都必须按固定提交重新核实。

遵循[功能变更指南](feature-change-guide.zh.md)、[工作流职责](workflow.zh.md)和[迁移规则](database-migrations.md)。实施跨越现有所有者，不引入第二套工作流执行引擎。

## 当前实现约束

- `crates/application/src/workflow_run/engine/graph.rs` 中的 `WorkflowGraph::parse` 在每个作用域内拒绝环；`node_type.rs` 执行 Start、Agent、Condition、Loop 和 Output。
- `engine/branch_projection.rs` 按节点 ID 投影状态；`engine/variable_pool.rs` 与持久化 Condition 决策使用运行级节点选择器。同一个定义节点重复执行，需要这三个所有者都支持执行作用域。
- `engine/engine.rs` 在调度结束时完成整个运行，并在运行历史中检查重复成功的 Output。子图完成需要独立边界。
- `crates/db/src/repository/workflow_run_engine.rs` 拥有完成、取消和重跑的事务；`crates/backend/src/workflow/run/` 拥有会话、人工完成、前置依赖准备和启动恢复。
- `packages/workflow-runtime/src/types.ts` 已列出前端 `loop` 类型，但不代表生产执行已支持；扩展前应核对编解码、编辑器目录、示例和校验。
- 真实运行视图使用契约查询和轮询；部分 artifacts/HITL 设施仍使用内存 runtime。循环执行及历史必须接真实契约链路，并显式组合测试适配器。

## 已交付的首版语义

以下默认值已由当前编辑器、解析器、调度器和仓储实现。

| 事项       | 已交付行为                                                                               |
| ---------- | ---------------------------------------------------------------------------------------- |
| 结构       | 单层 Loop 容器，轮次串行；单轮内支持普通分支和汇合                                       |
| 入口       | 显式容器归属与唯一合成子图入口；至少执行一轮                                             |
| 状态       | 有类型的跨轮变量，从常量或可见上游选择器初始化                                           |
| 反馈       | 显式声明本轮值到下一轮跨轮变量的映射                                                     |
| 退出       | 活跃子图执行结束后判断类型化 `until` 条件；复用 Condition 求值                           |
| 上限       | 必填正整数最大轮数；建议默认 5、上限 100，前后端均校验                                   |
| 顺序       | 解析反馈值，基于已完成轮次判断退出，再原子退出或推进；所有反馈赋值读取同一份赋值前变量池 |
| 达到上限   | 退出条件仍为假时，返回类型化上限错误，并保留最后一轮供检查                               |
| 输出       | 成功时导出显式命名的 Loop 输出；外部节点只在 Loop 完成后读取                             |
| Agent 执行 | 每轮每节点新建 NodeRun 与 Session，沿用模型、Skill、MCP 和输出契约行为                   |
| 人工反馈   | 支持在 Loop 内使用现有 interactive Agent，包括等待、后续对话和手动完成                   |
| 工作区     | 复用运行选定的 Workspace，文件修改跨轮累积                                               |

首次交付不包含任意回边、嵌套 Loop、数组 Iteration、自动重试、跨轮复用同一会话或独立的轮中 Break 节点。模型必须明确拒绝不支持的形式。评审节点可通过结构化输出表达批准结果，由 Loop 的 `until` 条件消费。

示例：初始化 `draft = ""`、`feedback = ""`；写作节点读取需求与跨轮值；评审节点产出 `approved`、`feedback`；反馈映射传递新草稿与评审意见；`approved == true` 时导出草稿，否则开始下一轮。

## 图与变量所有权

序列化图只声明一份权威容器归属；React Flow 父子布局与运行时子节点集合由该声明推导，避免在多层手写维护子节点列表。为新图结构定义版本或确定性解码规则；旧平面快照解码到根作用域，不重写不可变发布快照。

校验 ID 唯一、归属、子图入口、可达性、各作用域无环、无跨边界连线、合法结果绑定、轮数和类型。外部依赖通过可见容器输入进入，结果通过 Loop 输出离开。父子归属环和非法导入必须在创建会话或物化 Skill 前失败。

每轮拥有全新的变量值集合和私有 Condition 决策。外层只读输入与全局变量按既有作用域策略可见。跨轮变量有显式初始值，首轮不会读取未赋值的“上一轮输出”。节点不能写入其他轮次变量池，也不能隐式修改外层值。类型检查、模板、结构化选择器和工作区文件验证继续使用现有所有者。

轮次结束时解析配置的反馈和结果选择器，缺失值明确报错。不能意外读取未激活分支的值，用户必须绑定当前路径可用的变量。同一容器输出边界内结果名唯一。子图通过容器结果边界完成，不通过 Output 节点完成顶层 Run。

## 持久化执行模型

### 已实现的图格式

容器快照使用 `schemaVersion: 2`。Loop 是根层节点，配置为 `data.kind: "loop"` 和 `data.loopConfig`。子节点通过 `data.containerId` 指向 Loop；若序列化渲染器的 `parentId`，两者必须一致。根图与每个循环体都要求一个 Start 节点，且所有节点可达。拒绝嵌套容器与跨作用域连线。旧的扁平快照保留原有解码行为。

`loopConfig` 包含 `maxIterations`、`variables`、`until` 和 `outputs`。变量包含 `name`、`valueType`、`initial` 和 `feedback`。初值使用带标签的 `{ "kind": "constant", "value": ... }` 或 `{ "kind": "variable", "selector": ["node", "variable"] }`；反馈为选择器数组。`until` 复用 Condition 的 `logic` 与 `conditions` 语法。输出形如 `{ "name": "result", "variableSelector": ["child", "output"] }`。

初值可引用全局变量和外层上游节点。反馈、终止条件与导出可引用完成后的循环体、跨轮变量、全局变量和外层上游值。外层节点必须读取 Loop 导出的结果，不能直接引用子节点。解析层边界不能替代运行时的变量声明、值类型、缺失值和未激活分支检查；这些检查必须在开放执行前完成。

### 持久化实现

引入领域所有的执行作用域和 Loop 进度，最终 Rust 命名在实施时确定。根作用域表示今天的平面执行；轮次作用域记录父 Loop NodeRun 与轮次索引。NodeRun 引用作用域，同时保留唯一执行 ID 与定义节点 ID。

- 持久化作用域身份、父级归属、轮次、生命周期、当前节点实例、变量值和私有分支决策。复用类型化变量池表示，但每项执行事实只有一个权威存储位置。
- 为 `(scope_id, node_id)` 和 `(loop_node_run_id, round_index)` 建立唯一约束。父子作用域及节点会话绑定必须属于同一 Run。重跑创建新的根执行代次，旧回调不能作用于新代次。
- 用带关联数据的枚举表达 Loop 进度，例如执行子作用域、携带原因的终态；避免用一组关系松散的可选字段拼接状态机。
- 将最后一个子节点完成、反馈值、退出决策，以及下一作用域创建或父节点完成原子提交。恢复后的调度器可以派发已创建作用域，不会重复创建它。
- 保留每轮历史 NodeRun、输入、输出与 Session。未开始节点仍通过投影表达；真正的人工等待由已绑定执行实例区分。
- 命令与回调沿用每 Run 串行门、事务守卫和执行 ID 校验。重复或迟到回调不能重复释放后继或推进循环。

在 `crates/db/src/migration` 新增有序 Rust 迁移，提供 `up` 和 `down`，不修改已发布迁移。把旧 Run 与 NodeRun 回填到根作用域，保留状态、payload、时间及会话。必须测试仓库真实的自动降级行为：旧程序绝不能继续执行被扁平化的活跃 Loop。接受 down 迁移前，明确不支持的循环执行数据如何安全终止或归档，并证明再次升级安全。

无需新增 Workspace 或 Skill 目录布局。基线旁文件继续以唯一 NodeRun ID 命名。若实施中发现额外旁文件布局需求，必须明确冲突处理、迁移或隔离，并复用 `ora-utils::path`。

## 调度、会话与恢复

将作用域调度和 Loop 状态迁移提取到职责集中的私有模块，避免继续扩大已有大型 engine、executor 文件；相关测试与不变量随实现迁移。工作流专用调度留在 `ora-application`，只有真正独立于领域的辅助逻辑进入 `ora-utils`。

调度器把 Loop 派发为复合 NodeRun，复用 DAG 规则执行活跃子作用域，只有成功退出后才完成父节点。等待中的子节点让父节点保持活跃。Run 完成判定考虑活跃作用域及复合节点，子图结束不会提前完成整个 Run。按作用域处理 Output，同时保留既有平面工作流行为。

部署遍历子图，校验 Agent 前置依赖并冻结 Skill 回执。每轮使用这些回执、冻结图和本轮已提交变量。节点提示词包含有用的轮次上下文。人工操作定位到 NodeRun ID，沿用现有完成认领机制，避免后续对话与手动完成竞争。

取消先提交整个所属作用域树的终态，再尽力清理 Session。子节点失败使 Loop 与 Run 失败，并明确收束、停止活跃兄弟节点，不再创建下一轮。重跑保留冻结部署输入并建立全新执行状态。删除保护覆盖复合节点、等待中的子节点和活跃会话，绝不删除共享 Workspace 或用户文件。

启动恢复只续接持久化的调度间隙，保留合法人工等待，并按现有策略将中断的 Agent 执行标为失败；不自动重放副作用未知的工具。测试下一作用域创建前后、派发前后的崩溃。文件基线缺失按现有所有者策略降级变更报告。并行 Agent 共享 Workspace 时，差异表示时间窗口内的变化，不能保证修改独占归属。

## 契约与 Desktop 界面

扩展既有 workflow/run DTO，提供实际消费者所需的作用域、轮次、父执行、终止原因和历史信息。项目列表保持轻量，历史过大时按需加载轮次详情。优先扩展现有 get/list 操作，仅在历史视图需要时增加专用轮次查询。

新增操作时，分别在 `crates/contracts` 声明 DTO、`xtask/src/frontend/namespaces` 声明逻辑操作、`apps/desktop/src-tauri/bindings` 声明 Desktop 绑定与权限，并在工作流领域句柄实现行为。复用请求和流生命周期辅助设施。通过 `task export-contracts` 生成接线，使用 `task check:contracts` 验证；不手改生成的 TypeScript DTO、转发、分发或权限。

编辑器增加 Loop 容器、子图入口、类型化初始变量、反馈映射、退出条件、轮数和输出配置。覆盖拖动与重新归属校验、选择、删除、带 ID/选择器重映射的复制粘贴、撤销重做、自动保存、版本预览、复制工作流及导入导出。编解码保留注释和画布数据。后端验证为权威，使用共享样例验证前端诊断与其一致。

Theater/Overview 展示 Loop 进度和终止原因，允许选择轮次及其 NodeRun/Session，刷新与切换视图保留选择。当前轮投影与完整历史分开，避免不同轮次相同节点 ID 互相覆盖。state/data 拥有查询键和失效策略，功能所有者拥有翻译。切换轮次或卸载时释放所属 observer、timer 和订阅。
