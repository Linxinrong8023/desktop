四张表，一条证据链

从 run_id 出发：先确定哪次执行，再确定冻结版本，最后展开实际启动过的节点。

workflows 1 ─── * workflow_snapshots │ │ │ └── 1 ─── * workflow_runs │ │ └──────────────────────────────────────┘ └── 1 ─── * workflow_node_runs │ └── session_id? ─── sessions
表 一行代表 关键关联 创建时机
workflows 一个稳定工作流身份 published_snapshot_id 创建工作流
workflow_snapshots 一份 Draft 或发布图 workflow_id 创建 Draft / 发布
workflow_runs 一次具体执行 workflow_id, snapshot_id, workspace_id 用户创建 Run
workflow_node_runs 一个真正开始过的节点执行 run_id, session_id? 节点被调度启动

状态整数

0Pending

未开始，或交互节点等待输入。

1Running

正在执行。

2Succeeded

成功终止。

3Failed

失败终止。

4Cancelled

取消终止。

不要混淆：workflow_runs.run_status 和 workflow_node_runs.status 使用相同整数映射，但描述的是不同层级的状态。Run 的公开状态还可能把“运行中且存在等待节点”投影为 AwaitingInput。
