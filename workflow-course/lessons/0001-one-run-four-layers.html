一条工作流的四层生命线

先不钻代码。我们用“自动审查一次 PR”走完从画布、版本、数据库到 Agent Session 的闭环。你会得到以后读代码和排故时最重要的一张地图。

本课胜利条件：能用 90 秒讲清一次 Run 与一份 Workflow 的区别

先看一个具体故事

Scenario

你在编辑器画出 Start → Agent（审查代码）→ Output，保存草稿，发布为 v1，然后在项目的 Main Workspace 中启动一次运行。运行到一半，你又修改了草稿里的 Agent 提示词。

核心问题：正在执行的那次运行会不会突然使用新提示词？答案是不会，因为 Run 钉住的是创建时选择的已发布 Snapshot，而不是持续变化的 Draft。

01 · Author编辑 Draft

React Flow 产生 nodes、edges、viewport 的 JSON 文档。

02 · Publish冻结 Snapshot

复制草稿图，生成不可变版本，并更新激活指针。

03 · Create创建 Run

绑定已有 Workspace，并钉住一个发布快照。

04 · Schedule解析 DAG

校验图，找 ready set，按前驱约束推进节点。

05 · Execute驱动 Session

Agent 在 Ora Session 中工作，结果回写 NodeRun。

四层，不要混着讲

Layer 1

编辑与展示

编辑器负责画图、参数、草稿自动保存、发布和版本预览；Theater / Overview 负责展示一次运行。画布位置是展示信息，不等于执行顺序。

Layer 2

应用用例

ora-application 负责创建、更新草稿、发布、回滚、激活，以及 Run 的创建和控制。它通过 trait 依赖存储、时钟和执行器。

Layer 3

SQLite 持久化

ora-db 保存定义、快照、Run 和 NodeRun。CRUD 对 graph 主要按不透明文本处理，不替 workflow-run 应用层验证图拓扑。

Layer 4

调度与 Agent 执行

workflow-run 应用层在创建 Run 时解析结构，启动时重新解析并检查可执行性；随后引擎按 DAG 调度，ora-backend 把 Agent 节点接入真实 Session。

四张表分别回答什么

workflows

“这套流程是谁？”稳定 id、名称、当前激活的发布快照指针。

workflow_snapshots

“某一版本的图长什么样？”唯一 Draft 与多个不可变发布版本。

workflow_runs

“哪一次执行发生了什么？”Workspace、冻结快照、整体状态、输入输出和时间。

workflow_node_runs

“那次执行中的某个节点怎么样？”节点状态、Session 关联、输入输出、错误和时间。

排故口诀：先拿 run_id，再看 snapshot_id，最后按 node run + session 追踪。不要一上来盯着当前草稿，因为失败的 Run 可能执行的是旧版本。

今天只记住五条不变量

  • Workflow 是稳定身份；Snapshot 才承载版本化的图。
  • 每个 Workflow 恰好有一个可编辑 Draft；发布会复制图，不会把 Draft 本身改成发布版。
  • Run 钉住 Snapshot 和 Workspace；后续草稿修改不能改写这次执行。
  • 图由 workflow-run 应用层解析为 DAG：创建 Run 时先做结构解析，启动时重新解析并检查 Start、受支持类型与节点可达性。
  • NodeRun.output 不是完整对话；完整 Agent 历史属于 Session。
Interview pressure

面试官会怎么追问

为什么不让 Run 直接读取最新 Draft？

因为 Draft 会持续变化。若执行途中重新读取，会破坏可复现性、审计和故障定位；同一个 run_id 甚至可能前后执行不同逻辑。钉住不可变 Snapshot，把“作者继续编辑”和“已有运行执行”隔离开。

为什么数据库保存完整 React Flow JSON，而不是立刻拆成 nodes / edges 表？

定义 CRUD 只需保存和版本化作者文档，保持图为不透明快照能降低写入模型复杂度并保留画布元数据；代价是数据库难以按节点查询，结构校验必须由启动阶段的图解析器承担。

为什么还需要 WorkflowNodeRun，直接写 WorkflowRun.state 不行吗？

节点级记录提供独立状态、时间、错误、Session 绑定和输出，是并行调度、局部排障与恢复的最小持久化单位。只用一个大 state blob 会让并发更新、查询和约束变得模糊。

闭卷检索：现在就测

1. 发布后再改草稿，已有运行读取哪份图？

2. 一个节点从未被调度启动，数据库怎样表示？

3. 冻结图的 DAG 结构主要由哪一层验证？
