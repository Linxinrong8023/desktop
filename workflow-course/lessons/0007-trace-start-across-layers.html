Lesson 0007 · 端到端调用链

同一个“启动”，
跨过七层代码

UI 只表达用户意图，Contract 传递命令，Backend 串行化同一 Run，Application Engine 决定状态机，Database Adapter 原子落库，Agent Executor 才负责真实 Session。沿这条链排查，才不会在错误的层翻日志。

本课胜利条件：能从 handleStart 一路说到 tokio::spawn，并按症状指出最可能的故障层

先区分两个事故

事故 A · 同步启动失败

点击后立即弹 Toast

mutateAsync() 直接抛错，没有进入 Theater，也没有 Agent NodeRun。优先查传输、启动校验、Run 状态或启动事务。

事故 B · 异步执行失败

先 Running，稍后 Failed

启动命令已经成功返回，Agent NodeRun 也已落库；后台 warm、模型、Prompt 或 ACP 链随后失败。

一条真实启动调用链

01 · PresentationhandleStart()

读取当前 run.id，调用 mutation；成功后进入 Theater，失败则显示 Toast。

02 · State HookuseStartWorkflowRun()

调用 Contract Client；成功后失效 run detail 查询，让 UI 重新读取数据库状态。

03 · ContractstartWorkflowRun

请求只携带 runId；生成 Client 不知道 DAG、SQLite 或 Session。

04 · Tauri Adapterstart_workflow_run

把 camelCase operation 映射到桌面命令，再转给共享 Backend。

05 · Backend按 run_id 加锁

串行化 start、cancel 与 callback，随后调用 WorkflowRunControlHandler。

06 · ApplicationEngine.start()

解析冻结图、检查可执行性、启动 Run，并循环计算 ready wave。

07 · AdaptersDB + Agent

SQLite 先创建 Running NodeRun；Agent Executor 再用 tokio::spawn 后台执行。

每一层负责什么

层 负责 不负责
UI 触发命令、Loading/Toast、进入 Theater 保证幂等、计算 Ready
Contract/Transport 稳定请求响应形状、operation 到命令映射 工作流业务规则
Backend 组合真实 Adapter、按 run_id 加锁 复制 DAG 状态机
Application Engine 图校验、状态迁移、Ready、回调后续调度 直接写 SQLite、直接驱动 ACP
DB Adapter 事务、条件更新、NodeRun 与 current_nodes 选择 Agent 模型、组装 Prompt
Agent Executor warm/attach/config/prompt/ACP/callback 自行决定 DAG 后继

同步链在哪里结束

Engine.run_schedule()
  → start_ready_nodes()       // Running NodeRuns 已提交
  → NodeExecutor.dispatch()
       → tokio::spawn(...)    // 异步分界点
       → 立即返回
  → 重新读取 NodeRuns
  → 发现 Agent 仍在 in_flight
  → startWorkflowRun 返回 Run = Running

dispatch() 返回类型是 ()。它只把任务交给后台， 不等待 warm、Session、模型或 Agent 成功。因此“启动命令成功”只承诺当前执行 wave 已建立，不承诺 Workflow 最终成功。

Interview pressure

三句必须说准确

UI 为什么不能保证启动幂等？

UI 禁用按钮只能改善体验；网络重试、多窗口和直接调用仍可能重复。正确性由 Backend 的 per-run lock 与数据库条件事务共同保证。

Application Engine 为什么不直接调用 ACP？

Engine 只依赖 NodeExecutor 接口，保持 DAG 状态机可通过 fake executor 测试；生产 Backend 提供驱动真实 Session 的 Adapter。

启动成功后为什么仍可能很快 Failed？

启动链只保证当前 ready wave 持久化并派发。Agent 的 warm、模型选择、Prompt 和 ACP 都位于 tokio 后台任务中，错误稍后通过 fail callback 写回。
