Lesson 0005 · 产品闭环

编辑器里有名字，
不等于运行时能执行

Ora 当前只有 Start、Agent、Output 三种生产节点形成执行闭环。其他名字可能只存在于解析器、兼容代码或 mock 能力表中。定位“为什么工作流无法启动”时，必须先判断节点处于哪一层。

本课胜利条件：看到一种节点，就能判断它是可执行、已识别但拒绝，还是仅有原型元数据

事故现场：Condition 已经发布，却无法启动

Incident

Start → Condition → Agent → Output 已保存为 Draft，也成功发布了 Snapshot。

创建 Run 时，后端能够把 condition 解析成已知 NodeType；但真正点击启动时， first_unsupported_node() 会发现它不属于 v1 可执行集合，Run 在调度 Start 前被拒绝。

当前生产节点：只有三个

节点 有没有 Session 如何完成 主要数据
Start 没有 调度器同步完成 把 Run input 写成 Start NodeRun output
Agent 有 ACP Session 异步回调；可选 HITL Role、Skill、Prompt、上下文、最终回复、文件变化
Output 没有 调度器同步完成 用两个换行拼接直接前驱的 NodeRun outputs

Start 与 Output 都是控制节点：它们仍会创建 NodeRun，并经历 Running → Succeeded，只是没有外部 Session，也不等待异步回调。

三层能力矩阵

生产可执行

Start · Agent · Output

后端解析器认识，启动校验接受，调度器也有真实完成路径；当前节点栏只展示这三种。

已识别但拒绝执行

Prompt · Condition · Tool

Rust NodeType 能解析这些字符串，但 supported() 返回 false，启动 Run 时明确报错。

mock / prototype 元数据

Junction · Human · Loop · Subflow

前端 mock 中有名称、表单和测试，但当前节点栏隐藏；Rust 解析器也没有这些 NodeType。

同一个“不能运行”，会在不同时间暴露

01 · Draft可以保存

Definition CRUD 把 React Flow JSON 当作不透明文本，不判断节点执行闭环。

02 · Publish可以冻结

发布复制 Draft 图成为 Snapshot，不因为节点只有原型元数据就自动实现它。

03 · Create Run先解析图

完全未知的类型在这里就可能解析失败；已知但不支持的类型仍可进入 Run。

04 · Start Run检查可执行性

缺少 Start、包含已知但不支持节点、存在不可达节点都会拒绝启动。

为什么保留“认识但不执行”的类型？

  • 解析器可以给出明确的 unsupported node type condition，而不是把节点静默跳过。
  • 旧数据或直接 API 输入不会因为前端节点栏隐藏就失去可诊断性。
  • NodeType 注册不等于 NodeExecutor 已实现；显式门禁阻止半成品进入调度器后永久 Running。
  • 前端还会把遗留的 prompt / model 节点升级成 Agent，但这属于兼容加载，不是独立 Prompt 节点执行器。

故障定位：先看失败发生在哪一层

症状 优先判断 证据位置
节点栏根本没有 Condition 当前产品主动隐藏未闭环节点 AVAILABLE_NODE_KINDS
导入 Junction 后创建 Run 失败 Rust 解析器完全不认识该类型 Run 创建时的 GraphError
Condition 的 Run 已创建但启动失败 已知节点没有 v1 执行闭环 WorkflowValidationError
Start / Output 瞬间完成且没有 Session 正常同步控制节点行为 对应 NodeRun 状态与 output
Agent 长时间 Running 进入 Session 执行链后卡住 session_id、NodeRun.error、Session 历史
Interview pressure

不要把“有代码”说成“有功能”

前端有 Condition 表单和测试，为什么不能说 Condition 已实现？

因为它们来自 mock/prototype 能力层。生产节点栏主动过滤 Condition，Rust 启动校验也明确拒绝它；没有从配置、调度、执行到持久化结果的闭环。

为什么不让不支持的节点进入调度器后再失败？

当前调度器只同步完成 Start/Output，只为 Agent 派发执行器。其他节点若进入 ready wave，会得到 Running NodeRun，却没有任何完成者。启动前拒绝能避免永久悬挂。

Output 节点算不算 Agent 节点？

不算。它是无 Session 的同步控制节点，只拼接直接前驱 output；需要智能总结时，应在它之前放一个真正的汇总 Agent。
